The new Console is being rebuilt on [shadcn-admin](https://github.com/satnaing/shadcn-admin)
conventions, one page per PR (#302). **It is not embedded yet**:
`internal/ui/static` still serves the Vue console from `frontend/` at `/ui/`.
The switch happens in a final cutover PR once every page has reached parity.

Rules for every migration PR:

- The backend API does not change. Each page makes the same requests with the
  same parameters as the Vue page it replaces.
- Operator capabilities stay the same; nothing is dropped in the move.
- Wording reuses `frontend/src/locales/*.json`, so both consoles read the same.
  Strings only this Console needs live in `consoleOnly` in `src/lib/i18n.tsx`.

## Layout

| Path | What lives there |
| --- | --- |
| `src/routes/` | TanStack file routes; hash history keeps the old `#/tasks`-style links |
| `src/components/layout/` | App shell: sidebar, header, auth banner, settings |
| `src/components/ui/` | shadcn/ui components (`npx shadcn@latest add ...`) |
| `src/context/observation.tsx` | One refresh = `/api/dashboard` + `/api/cluster/overview` + `/api/workers` |
| `src/features/<page>/` | Page code, ported from the matching Vue view and composables |
| `src/lib/` | API client, token storage (same `binlog_server_token` key), i18n |

## Develop

```bash
cd console
npm ci
VITE_API_TARGET=http://127.0.0.1:8080 npm run dev   # http://localhost:5174
npm run build                                      # type-check + production bundle
```

`src/routeTree.gen.ts` is generated by the TanStack Router plugin on dev/build;
commit it with route changes.
