The operator Console, built on [shadcn-admin](https://github.com/satnaing/shadcn-admin)
conventions (#302). `make ui-build` builds it into `internal/ui/static`, which the
server embeds and serves at `/ui/`. The classic Vue console (`frontend/`) is built
into `internal/ui/classic` and served at `/ui-classic/` for one release; after that
release `frontend/` and `internal/ui/classic` are deleted.

Rules that held for every migration PR, and still hold:

- The backend API does not change. Each page makes the same requests with the
  same parameters as the Vue page it replaces.
- Operator capabilities stay the same; nothing is dropped in the move.
- Wording lives in `src/locales/*.json`; the classic console reads the same files.
  Strings only this Console needs live in `consoleOnly` in `src/lib/i18n.tsx`
  (deep-merged). `src/locales/catalog.test.ts` fails when either console uses a
  key that a catalog lacks.

## Layout

| Path | What lives there |
| --- | --- |
| `src/routes/` | TanStack file routes; hash history keeps the old `#/tasks`-style links |
| `src/components/layout/` | App shell: sidebar, header, auth banner, settings |
| `src/components/ui/` | shadcn/ui components (`npx shadcn@latest add ...`) |
| `src/context/observation.tsx` | One refresh = `/api/dashboard` + `/api/cluster/overview` + `/api/workers` |
| `src/features/<page>/` | Page code, ported from the matching Vue view and composables |
| `src/lib/` | API client, token storage (same `binlog_server_token` key), i18n |

## Migration status

| View | Status |
| --- | --- |
| Shell, settings (token + language) | migrated |
| Tasks, Alerts | migrated |
| Task detail drawer (`#/tasks/:id`, `#/alerts/:id`) | migrated; after Start/Stop it polls `GET /api/tasks/{id}` until the state leaves STARTING/STOPPING, then reloads |

| Overview, Sources, Workers | migrated |
| Cutover (embed in `internal/ui/static`, classic at `/ui-classic/`) | done |

## Develop

```bash
cd console
npm ci
VITE_API_TARGET=http://127.0.0.1:8080 npm run dev   # http://localhost:5174
npm test                                           # vitest: pure helpers + locale key coverage
npm run format:check                               # prettier
npm run build                                      # type-check + production bundle (base /)
```

`make ui-build` (from the repo root) runs `npm test`, builds with `VITE_BASE=/ui/`,
syncs into `internal/ui/static`, and runs `scripts/check-ui-bundle.sh`. Commit
`internal/ui/static` with UI changes: CI checks the committed bundle.

Live regression checks against a running server: see `tests/live/README.md`.
Playwright regressions with mocked APIs (moved from `frontend/tests/e2e`): `npm run test:e2e`, see `tests/e2e/README.md`.

`src/routeTree.gen.ts` is generated by the TanStack Router plugin on dev/build;
commit it with route changes.
