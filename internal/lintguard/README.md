# lintguard

`go test` guard against new silent error paths in the backup data path (ADR 0009 phase 0, #326).

- `guard.go`: syntactic scanner for `_ = call(...)` and `if err != nil { log... }` with a log-only body.
- `ignored_errors_test.go`: scans `internal/{tasks,replication,binlog,upload}` and fails on any site not in `allowlist.go` at its reviewed count.
- `allowlist.go`: reviewed sites keyed `file:func:kind`, each with a reason. Entries marked `follow-up:` are known gaps for phase 1. `killLeftover` returns the KILL error (a TLS verify failure is warned, other failures are logged) so it is not a log-only site. `fillSealDigest` logs a failed `.seal-sha256` append and still uploads: the catalog digest is already on the row, and a missing ledger line only hides the segment from the rehasher when there is no catalog column. `Verifier.save` returns on a failed `.verify.json` write and leaves the progress dirty, so the next pass tries again; findings stay in the finding store. That return is not a log-only site. `peekMySQLGreeting` closes the raw socket on each error return while reporting the read error; `sourceSyncerTLS` best-effort closes its plaintext probe connection, the TLS decision does not depend on it.
- `guard_test.go` + `testdata/bad`: proves the scanner finds both shapes and ignores handled errors.

Not covered (by design, syntactic only): `v, _ := f()` blank error results, and errors dropped by not assigning a call's result at all. The full `errcheck`/`go vet` CI step needs a workflow edit and is tracked in the token-gaps handoff.

When the test fails: report a finding, return the error, or add the site to `allowlist.go` with a reason in the same PR. `copyOwnership`, `writeStopExpiredLocked`, and `markRestoredFailedLocked` may set `State` because they record a decision `ownership.Step` already made, or a restore that has no safe position. `leaveDiskTombstone` ignores a failed marker write. `deleteStoredRefusalsLocked` logs a failed delete and leaves the row, which keeps the claim blocked.
- `task_state_test.go`：AST 检查。`internal/tasks` 里设置任务 `State` 只能在 `commitTransitionLocked` 或列明理由的 runner/控制回路配方里；操作员动作函数不得直接赋值 `s.tasks[...]`、删除 `s.tasks`、调用 `persistTaskLocked`，必须调用 `commitTransitionLocked`/`commitDeleteLocked`。白名单里不存在的函数也会报错。`yieldForResumeLocked`（§29）记的是本进程已经放弃的这一轮 dump，不落盘 desired STOP，所以和 `yieldLostLeaseLocked` 一样在白名单里。`yieldFencedEpochLocked`（§29.10，#454）同样只把观察状态留在可认领的 `LEASE_DEGRADED`，不写 STOPPED。
- `managed_writer.go` + `managed_writer_test.go`（P2-4，#342）：任何名为 `Report`/`Resolve`/`report`/`resolve` 的调用（方法、logger 方法或函数值）若参数提到健康评估器 Managed 的 kind（`tasks.FindingX` 常量或其字符串）即失败；热路径改用 `SignalFailure`/`SignalSuccess`。只由评估器推导、没有 `tasks.FindingX` 常量的 kind 记在 `managedWithoutConstant`（含 P2-5.4 的 `ORPHAN_ROW` 与 `SEAL_FACTS_ABSENT`，以及 P2-6.1 的 `HEALTH_STALE`）。`testdata/managed` 覆盖各种写法。
- `kill_by_pid_test.go`：`scripts/`、`.github/` 下所有已跟踪文件和 `Makefile`（不管扩展名和语言，注释也算；`.md` 是说明文字，不扫）里不能出现 `pkill`、`killall`、`pgrep`、`pidof`：共享机器上别的运行用的是同样的命令行，按名字找或杀进程会误伤，脚本只杀自己启动的 PID（`$!` 或 pidfile）；`upgrade-legacy-failback.sh` 每次启动 server 都把 PID 记进 pidfile，cleanup 只杀这些。
- `release_gate_test.go`（production-readiness J3）：读 `.github/workflows/release.yml` 和 `e2e.yml`。`release.yml` 必须有 `ci` job 调用 `./.github/workflows/e2e.yml`，其余 job 都 `needs: ci`（`release-prep` 只读文件，和 `ci` 并行跑，`release` 必须 `needs` 它）；`e2e.yml` 必须有 `on: workflow_call`。条件和 `continue-on-error` 由 `release_walk_test.go` 管。
- `release_walk_test.go`：从 `release` job 出发，走它通过 `needs`（递归）依赖的每个 job，以及这些 job 调用的本地 workflow（`e2e.yml`）里的每个 job。这些 job 和它们的每个 step 上：`continue-on-error` 只能不写或写 `false`（表达式也不行；job 级别设了它，依赖方看到的结果就是 success）；`if` 只能不写，或者正好是 `allowedIfs` 表里的一行（精确文本，`{profile}` 代表去掉 `e2e-` 前缀的 job 名），每行带一句理由。被调用 workflow 里跳过的 job 算成功，跳过的 step 不让 job 失败，release 上的 `always()`、`!cancelled()` 会在 gate 失败后照样发布，所以别的条件一律失败；以后真要加条件，只在这张表里加一行或改一行并写理由，报错会指明这张表所在的文件。每行限定 workflow、job（或任意 job）以及是 job 自己的 `if` 还是 step 的 `if`；`always()`、`failure()` 对任意 step 都成立，改 step 名不影响，只有 release 的两个发布 step 按名字限定。表里每一行都必须在今天的 workflow 里用到。`unit-and-e2e` 那行把每个单 profile job（含 `fault-matrix`）的名字逐个列全，新增 profile job 时要同步加进 workflow、`run-suite` 和这行文本。
