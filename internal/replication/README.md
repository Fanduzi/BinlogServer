# internal/replication Module

## Files
- `mysql_runner.go`: 复制主执行流程（含 open segment 元数据及进度更新、LATEST 与已在 master file/pos 的 FILE_POS 立即 at-tip、从源文件中部开始时把 format description 写在第一个业务事件前面且不推进 checkpoint 也不计延迟、已经有事件的分段不再写第二条、只有 description 还没有业务事件时不落盘、idle 仅在 dump 达到 master file/pos 时标 at-tip、heartbeat 跳过落盘）。dump 一连上就把 MySQL 连接号交给调度器。关掉 dump 时用当前源密码（调度器绑上的那份，或这次任务上的密码）`KILL` 这条 Binlog Dump；下一次 `StartSync` 之前再 `KILL` 同一个号，KILL 没有确认就不会再 `StartSync`。Stop 期间改了密码，旧线程不会和新 dump 一起留下。KILL 连不上源库时把连接号交给调度器，任务仍写成 STOPPED。拉流设置 15 秒的 `master_heartbeat_period`。对端收到 FIN/RST 时大约一个心跳周期拆掉 dump；半开路径上心跳写不阻塞，`net_write_timeout` 不触发，源库要等多久取决于它自己的 TCP 重传（Linux `tcp_retries2` 默认约 15 分钟）。本进程在路径仍是黑洞时缩短不了这段等待。停止后再启动时调用 `tasks.NextResumePosition`：从本地最高 open 分段最后一个完整事件的 `end_log_pos` 续传，不跳到当前 `SHOW MASTER STATUS`；该分段改名到新 epoch 后继续追加，字节跨停止点连续。epoch>1 且本机 data dir 没有 `.open.eN` 完整事件时，用目录里的 `file_path`：目录能读就从那里最后一个完整事件续写，不另起目录，也不把同一源文件再封一次；`state=OPEN` 的裸源文件名在本机时改名为当前 epoch 的 `.open.eN` 再续。本机 `.open.eN` 只有 magic，或只有 `end_log_pos` 为 0 的文件头、没有完整事件时，从已保存的 checkpoint 续，并把该文件改名到当前 epoch。open 分段或未上传的封存分段读不到，并且 checkpoint 还不在已上传对象里，返回永久错误 `SEGMENT_NOT_ON_WORKER`，不建新目录。checkpoint 已经落在 `UPLOADED` 对象里时，从该对象读回字节再续，不从位置 4 重拉。封文件后把已 seal 文件交给注入的 handler 上传。封存行的 `start_pos` 和 `end_pos` 取该文件里连续事件链的起点和最后一个事件的 end log_pos。指向当前文件且 position 为 0 的 artificial rotate 不把复制位点清成 0。补登还没有目录行的封存文件时用同一套位点，已经 `UPLOADED` 的旧行不改。同一源文件名的每个 epoch 各占 `binlog_files` 一行。打开一个目录时，该目录里文件已经不在的 `OPEN` 行会删掉；别的目录里的行不动。后一次 `.open.eN` 不改写更早封存行的路径、上传状态、checksum 和 object key。该名字第一次封存仍用原来的对象键，叶子是源文件名，旧版本已经上传的对象不用重传就能下载和回放。已经有封存文件或另一条目录行时，后一次封存写成 `name.sealed.eN`，对象键叶子用这个名字。保留按磁盘文件名找到对应的那一行：`UPLOADED` 且 checksum 为 match 的分段按原规则删除，`UPLOAD_FAILED` 留下。打开文件时保留和 rotate 按 `(file_name, epoch)` 分页读 `binlog_files`，不再一次装入该任务全部目录行。接管一个已上传分段时把对象流式写到临时文件，复制完整才改成 open 分段；下载失败不留下会被当成有效位点的半截文件。这份 open 分段如果没有写出比已校验 `UPLOADED` 行更靠后的事件，转到下一个源文件时不再封成新 epoch，也不再上传一遍。目录行上的 checksum 仍是上传时的比对结果，这次复制不改它。打开文件时按有效本地保留清理只删除 `ClassifySegment` 判定为封存分段的名字；`.takeover-*`、`notes.txt`、`task-N.binlog` 和 open 分段留下，启动和 `materializeUploaded` 仍不清理 `.takeover-*`。保留清理过期封存分段：只配 `retention_days` 时 `checksum` 为 `match` 的已上传对象用目录里的 `object_key` 从桶里删除，并删掉该目录行；桶保留更长时，仍在桶保留内且 `checksum` 为 `match` 的 `UPLOADED` 只删本地。磁盘上 `checksum` 不是 `match` 的 `UPLOADED` 留下，并记成 `UPLOAD_FAILED`。没有元数据时用与上传相同的 object key，并按本地天数把对象一起删。还在保留期内的分段和任何 open 分段不删。配置了上传且有目录时，过期的 `UPLOAD_FAILED` / `LOCAL_ONLY` 封存文件和目录行留下，不返回错误，也不进入重试；同一文件只追加一次 `RETENTION_SKIPPED_NOT_UPLOADED`（message 带文件名和 `upload_state`）。`RetentionBlockedFiles` 是这次成功清理后仍留下的这类文件数，下次清理把已上传的删掉后归零。没有 `meta_dsn` 时仍按本地文件清理。没配上传但有目录时，本任务目录里已经没有本地文件、且没有远端副本的封存行删掉，并记一条 `RETENTION_REMOVED`（message 带文件名）；`file_path` 不在本目录的行留下。对象还在桶保留内的 `UPLOADED` 行留下。对象删除失败时本地文件留下，任务错误以 `OBJECT_PURGE_FAILED` 开头，下次打开文件再试。这次删除后来成功时，复制从下一个 binlog 文件继续，不会因为刚封存的文件已在磁盘上而停在 `sealed file already exists`。rotate 在打开下一个文件之前把 checkpoint 记到下一个文件。磁盘上 `checksum` 不是 `match` 的已上传文件不删，并记成 `UPLOAD_FAILED`。对象删除失败时不改 `checksum`。`KeepLocalSegments` 为真时不改写 adopt 保存的 `FILE_POS`，也不删除其它 epoch 的 `.open.e*`。若某个 open 分段的最后一个完整事件已经结束在该 `FILE_POS`，仍把该分段改名到当前 epoch 后追加，避免新文件只剩 magic 和位点之后的事件。对不上的分段留在原地，新字节写到当前 epoch 的新 open 文件。配置了上传时，封存行在 put 之前写成 `UPLOAD_FAILED`（带 object key）。进程在 rename 之后、这次写入之前死掉，下次启动（含租约接管）会把磁盘上的封存文件补成同样的 `UPLOAD_FAILED`，并把仍停在该封存 rotate 上的 checkpoint 挪到下一个文件，复制继续。已有的后台补传再上传并校验。这次 put 使用与补传相同的 `meta.timeout.upload_sec`；超时留下 `UPLOAD_FAILED`，拉流继续。没配上传时仍写 `LOCAL_ONLY`，不上传，有目录时的保留行为不变。以 GTID 启动的任务，每条已落盘事件的 checkpoint 带着当时已执行完的 GTID 集合（事务在 XID 或自动提交后才计入，未提交的 GTID 不写进去）。复制连接是 RawMode：GTID、QUERY、PREVIOUS_GTIDS 的 Event 是 GenericEvent，从事件体解码后再计入，XID 仍按事件头提交。rotate 记到下一个文件时同样带着。重启后续传仍先按 file/pos。StartSync 同步返回 1236，或 StartSync 已成功但第一条流错误是 1236，且该集合非空、还没有任何 dump 事件时，关掉这个 syncer，新建一个再 StartSyncGTID。GTID 流再返回 1236 则把错误交回去，不循环。没有这个集合时返回给 DBA 的文本，写明 MySQL 1236 以及源上的 binlog 已被清理（purged binlog）。file/pos 能读到事件时不改走 GTID。封存目标已经在磁盘上时返回永久错误 `SEALED_FILE_EXISTS`。checkpoint 写入不是瞬时元数据错误时返回永久错误 `CHECKPOINT_WRITE_FAILED`；瞬时错误原样返回。封文件前租约 epoch 不匹配时，`Run` 把它包成租约移交，调度器不把任务写成 `FAILED`。已经打开的 dump 在库内最多重连 5 次（每次约 1 秒）；仍失败则把错误交回调度器。LATEST 第一次解析出的 file/pos 在拉流前写成 checkpoint，`gtid_set` 为空；之后的重试从该位点续，不再重新解析 LATEST。没有元数据时本进程同样记住这个位点。源库重启后 sender 补的 artificial rotate（`end_log_pos` 0，不在源文件里，常常没有 CRC）不写入本地分段；它指向下一个文件时按最后一个真实事件封口并继续。这段如果还只有 4 字节 magic，不封存、不写目录、不上传。GTID 启动不创建 `task-{id}.binlog`，等这条 Rotate 给出源文件名再打开该名字。本地 open 分段末尾已经有这种事件时，续传用最后一个 `end_log_pos` 不为 0 的事件，同机接管不报 `SEGMENT_NOT_ON_WORKER`。

## Exports
- Runner 启停与进度上报。fresh LATEST，以及 FILE_POS 起点已经不落后于 SHOW MASTER STATUS（含 standalone adopt 续传，以及停止后从本地分段末尾续上且该位点已经不落后），在 StartSync 成功后立即按 at-tip 上报。请求位点之前的 format description（`log_pos` 为 0 或仍小于等于当前位点）在第一个业务事件写入时放在该事件前面，只写一次，不推进 checkpoint，也不参与 delay。已经有事件的分段不再写第二条。只有这条 description、还没有业务事件时不落盘，避免把续传位点退回 126。idle dump wait 仅在 dump file/pos 已达到（或不落后于）源库 SHOW MASTER STATUS 时标 at-tip；仍落后的 FILE_POS/GTID 保持 event header lag。停止后再启动（无 meta 的 standalone，以及有 checkpoint 的 catalog）从该任务 open 分段最后一个完整事件继续，源在停止期间写入的事件追加在同一分段，不从文件头重拉。standalone 被 kill 后没有任务元数据时，adopt 不带 start 保存的 `FILE_POS` 是最高分段的字节大小；该大小等于最后一个完整事件的 `end_log_pos` 时，start 同样把这段 open 文件改名到新 epoch 再追加，不跳到 `SHOW MASTER STATUS`，也不从位置 4 重拉。
- 源网络超时、拒绝、主机不可达及复制流 EOF/UnexpectedEOF 统一暴露 `SOURCE_UNREACHABLE`。已经打开的 dump 断线后，库内最多再连 5 次，大约 5 秒。这 5 次里连上，任务保持 `RUNNING`，`last_error` 不动。5 次仍失败，错误回到调度器，任务进入 `RETRY_BACKOFF`，`last_error` 以 `SOURCE_UNREACHABLE` 开头，并计入与初次连接失败相同的连续失败预算。LATEST 第一次解析出的 file/pos 在拉流前写成 checkpoint，`gtid_set` 为空；重试从该位点续，不再重新解析 LATEST。没有元数据时本进程同样记住这个位点。已有 checkpoint 的任务不改。GTID 任务的 `gtid_set` 仍按提交推进。已存在的封存文件是永久的 `SEALED_FILE_EXISTS`。非瞬时的 checkpoint 写入是永久的 `CHECKPOINT_WRITE_FAILED`；deadlock、connection reset、timeout 这类瞬时写入仍原样返回。封文件前租约 epoch 不匹配从 `Run` 返回租约移交。其余本地文件错误（含 append/flush）原样返回，由调度器第一次写成 `FAILED`。`OBJECT_PURGE_FAILED` 仍是可重试文本，不是任务失败。
- MariaDB 身份：`mariadb:<server_id>:<gtid_domain_id>`；MySQL 仍用 `server_uuid`。`flavor=mysql` 探测不到 `@@server_uuid`（空结果或 unknown system variable）时，永久错误 `SOURCE_IDENTITY_UNAVAILABLE` 提示这台源像 MariaDB，并要求 `flavor=mariadb`。`flavor=mariadb` 不读 `server_uuid`。
- 文件落盘、checkpoint 对接、随落盘进度更新的 OPEN/SEALED 生命周期元数据；上传与重试共用 `tasks.ApplySealedUpload`。保留清理在本地文件删除之前删除已上传对象；删除失败不把这次清理报成成功。配置了上传且有目录时，过期且未上传的封存文件不删。`local_retention_days` 短于 `bucket_retention_days` 时，仍在桶保留内且 `checksum` 为 `match` 的 `UPLOADED` 封存文件只删本地，对象和目录行留下；本地文件已经不在时，桶年龄用 `sealed_at`，否则 `uploaded_at`。只配 `retention_days` 时仍是一个截止时间。没配上传但有目录时，封存文件从本任务目录按年龄删除后，没有远端副本的目录行一并删除，并记一条 `RETENTION_REMOVED`。对象仍在桶保留内的 `UPLOADED` 行留下。rotate 在打开下一个文件之前把 checkpoint 记到下一个文件，并且记在封存上传之前，对象删除后来成功时复制从该文件继续。封存上传超时或崩溃留下的 `UPLOAD_FAILED` 由已有补传完成。
- 租约接管不搬数据目录。能读到 catalog `file_path` 的目录就在那个目录续写。读不到未上传的尾部则任务失败，错误以 `SEGMENT_NOT_ON_WORKER` 开头并带上缺失路径。本机上 `state=OPEN` 的裸文件名（epoch 0 写下的 `mysql-bin.NNNNNN`，没有 `.open.eN`）会改名为当前 epoch 的 `.open.eN` 再续写，不再因为这份文件在磁盘上却报 `SEGMENT_NOT_ON_WORKER`。本机 `.open.eN` 只有 4 字节 magic，或只有 `end_log_pos` 为 0 的文件头时，同样改名到当前 epoch，从已保存的 checkpoint 续，而不是 `SEGMENT_NOT_ON_WORKER`。封存的裸名不动。本机 open 分段末尾的 artificial rotate（`end_log_pos` 0）不算分段缺失。checkpoint 已在封存且 `UPLOADED` 的对象内时，从对象续，不从位置 4 重建。续到这段末尾再转到下一个源文件时，不再把同一份字节封成新 epoch 并上传第二遍。已经记在目录里的重复行，回放按源序号只留一条。
- GTID 任务的 checkpoint 在事件落盘后仍有可用的已执行 GTID，RawMode 下从事件体解码 GTID/QUERY。file/pos 续传在 StartSync 或第一条 GetEvent 收到 MySQL 1236（请求的 binlog 已被清理）时，关掉当前 syncer，用该集合新建 `StartSyncGTID`；没有这个集合时返回给 DBA 的文本，写明 MySQL 1236 以及源上的 binlog 已被清理（purged binlog）。已经读到 dump 事件，或 file/pos 能连上时，不改走 GTID。GTID 启动和这次回退都不写 `task-{id}.binlog`。无 CRC 的人工 Rotate 不进分段；只有 magic 的文件不封存。源库校验是 CRC32 时，新封存的分段可以用 `mysqlbinlog --verify-binlog-checksum` 读。
