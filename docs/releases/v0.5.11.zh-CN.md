# Binlog Server v0.5.11 中文发布说明

> 对应版本：`v0.5.11`

发布日期：2026-10-03

`v0.5.11` 是 `v0.5.10` 的认领并续传。`v0.5.10` 已经能列出遗留 binlog 目录。这一版把 `cluster_key` 和 source 接到其中一个目录上，之后的 start 才能在同一目录写下一段 epoch。没有 schema migration，没有新的配置键，Console 也不能 adopt。

## 核心变化

- standalone 没配 `meta_dsn`：`POST /api/tasks/{id}/adopt` 把 `cluster_key` 和 source 接到 `GET /api/tasks` 已经列出的遗留 `{data_dir}/{id}/` 上。id 仍是目录名。成功是 200。响应里没有密码。状态保持 `STOPPED`。adopt 不会开始复制。adopt 之前，`PUT /api/tasks/{id}` 和 `POST /api/tasks/{id}/start` 仍返回 400，正文是 `on-disk backup has no task metadata`，不会开始复制。没传 `start` 时，保存的位点是 `FILE_POS`，文件是最高封存分段或 `.open.e*` 分段的源文件名，位点是该分段的字节大小。显式 `start.mode` 会覆盖这个默认值。本次 tip `9b4ded4` 的试用：`mysql-bin.000007` pos 477，等于那个 `.open.e1` 的大小。随后 `POST /api/tasks/{id}/start` 返回 204，任务进入 `STARTING`，epoch 是 2，同一目录写出 `.open.e2`。原有分段还在。
- 配了 `meta_dsn` 时不会从磁盘发现目录。对不是目录任务的目录做 adopt，返回 404 `task not found`。试用的目录是 `99` 和 `42`。这种模式下 adopt 不会从磁盘创建任务。
- 不需要 schema migration。没有新的配置键。Console 没有 adopt 按钮。编辑仍走 `PUT`，在 adopt 之前一直被拦住。
- Quick Start、落地页、部署文档、配置模板和 workers API 示例里的版本钉在 `v0.5.11`。

## 升级影响

- `v0.5.11` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 配置键没有变化。`PRODUCTION=true` 仍要求非空 `--encryption-key`。
- standalone 没配 `meta_dsn`：`POST /api/tasks/{id}/adopt` 把 `cluster_key` 和 source 接到 `GET /api/tasks` 已经列出的遗留目录上。成功是 200，响应不带密码，状态保持 `STOPPED`，adopt 不会开始复制。adopt 之前，`PUT` 和 `POST` start 仍返回 400，正文是 `on-disk backup has no task metadata`，不会开始复制。没传 `start` 时，保存的位点是最高封存或 `.open.e*` 分段的源文件名和字节大小，模式是 `FILE_POS`。显式 `start.mode` 会覆盖这个默认值。试用：`mysql-bin.000007` pos 477，等于那个 `.open.e1` 的大小。`POST` start 随后返回 204，任务进入 `STARTING`，epoch 是 2，同一目录写出 `.open.e2`。原有分段还在。
- 配了 `meta_dsn` 时不会从磁盘发现目录。对不是目录任务的目录做 adopt，返回 404 `task not found`（试用目录 `99` 和 `42`）。这种模式下 adopt 不会从磁盘创建任务。
- Console 没有 adopt 按钮。编辑仍走 `PUT`，在 adopt 之前一直被拦住。`v0.5.10` 已经发布了遗留目录列表。这一版是认领并续传。
