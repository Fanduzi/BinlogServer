# Binlog Server v0.5.81 中文发布说明

> 对应版本：`v0.5.81`

发布日期：2026-10-27

v0.5.81 让 HTTP 关停变快，并让 `-race` 门禁变得确定（#535，取代 #532）。关停时，控制面和 worker 健康服务现在先关掉空闲的 keep-alive 连接和还没发出请求的连接，不再在它们身上耗完 5 秒的 HTTP 关停预算。CI 的 `race-and-vet` job 不再跳过任何测试，冷启动健康评估的目录遍历在 CI 里用内核记录的单次文件系统调用数和读取字节数封顶。修复 #439、#490、#504、#526、#534。没有新迁移（schema 最高 10，`minRequiredSchemaVersion` 仍为 6），没有新配置项，升级地板仍是 v0.5.51。生产就绪清单仍为 MET 20 / PARTIAL 6 / NOT MET 9；G1 不再把 #439 列为阻塞。

## 升级须知

- **没有迁移，没有配置变化。** schema 最高仍为 10，`minRequiredSchemaVersion` 仍为 6。从 v0.5.80 升级只需替换二进制。从 v0.5.79 或更早版本升级，v0.5.80 的说明仍然适用，包括 `upload.use_ssl` 默认值的变化。
- **有空闲客户端时关停更快。** 客户端持有空闲 keep-alive 连接或还没发请求的连接时，`SIGTERM` 不再被拖最多 5 秒；Tip QA 在开着空闲 keep-alive 时测得 0.01 秒退出。这类客户端会在关停时看到连接被关闭，需要重连，和任何一次重启一样。正在处理的请求仍有最多 5 秒完成。
- **回滚。** v0.5.80 用同一个 schema 和同一份配置，可以回滚二进制，只是有空闲连接时关停又会变慢。

## 修复

- **HTTP 关停（#535）：** `server.Shutdown` 对还没发请求的连接会一直等满 5 秒，也就是整个 HTTP 关停预算。现在关停先关掉空闲 keep-alive 和从未发请求的连接，关闭开始之后才变成 new 或 idle 的连接由 ConnState 钩子关掉。在途请求仍有 5 秒。
- **#439：** `TestApp_ProductionAuthProtectsRealRoutes` 在 `-race` 下偶发失败，因为应用没能按时关停。测试现在用自己的 HTTP client（开着 keep-alive）和 `t.TempDir()` 数据目录，关停能否在 2 秒内完成取决于生产代码的关闭逻辑。
- **#490：** `TestFailurePathMatrixMetaOutage` 和 `TestOpenEpochENOENTAfterTakeoverDoesNotFail` 在 `-race` 下不稳定。测试改为等可观察的结果（例如 finding sink 写完），不再看墙钟。
- **#504：** `TestOpenReplayArchive_MissingOpenSegmentIsNotOnProcess` 和 1500 段评估器测试在负载下不稳定。评估器测试改名为 `TestEvaluator_1500SegmentsNearLinear`，数遍历操作而不是计时（只保留 2 秒防挂死上限）。
- **#526：** `TestTaskRecords_StopAndDeleteApplyWhenSaveFails` 在完整 `-race` 套件里不稳定。
- **#534：** `internal/api` 的回放归档临时文件计数数的是进程临时目录，和 `internal/replication` 并行跑时互相干扰。回放归档临时文件现在放在 tasks 包内一个不导出的目录里，测试只数这个目录。

## CI

- `race-and-vet` 跑 `go test -race -count=1 ./...`，不再带 `-skip`。原先跳过的 6 个测试（#439、#490、#504、#526）重新在这里跑。
- `TestEvaluator_SyscallWalkNearLinear`（Linux）在 `strace -f -ttt` 下重新执行测试二进制，对 150 段和 1500 段各做一次冷评估，统计文件系统调用数，以及 `getdents64`、`read`、`pread64`、`readv` 返回的字节数。每次必须不超过每段 231 次调用加 16、每段 1506 字节加 4096，且 1500 段的两项总数都不超过 150 段的 10.5 倍（实测 23140 / 231117 次调用，150467 / 1500475 字节）。CI 和发布 workflow 里跑 `go test` 的 job 都装 strace；没有 strace 时测试失败。
- `TestEvaluator_1500SegmentsNearLinear` 在新的 `internal/binlog` 遍历接缝上数进程内遍历操作（每段最多 36 次加 16，实测 3612 / 36012），作为本地快速信号。
- 这些上限不覆盖：每段纯 CPU 或 sleep、只比较段名的循环，以及经 `mmap`、`sendfile`、`statx` 的线性读取（不计字节）。

- **#513（P2）：** 接管后，恢复运行的旧 owner 可能把 FAILED 写到新 owner 的任务行上，备份停到运维 Start。
- **#539：** 任务 start/stop 对源库的连接扇出偏大。
- **#514**、**#512**、**#494**、**#500**、**#502**、**#503**（P3）仍未关闭，**#487**、**#488**、**#451**、**#452**、**#455**、**#456**、**#446**、**#437**、**#438** 也是。`/api/findings` 还没有读超时（P2-7）。集群模式不跑巡检（A4 PARTIAL）。
