# Binlog Server v0.5.3 中文发布说明

> 对应版本：`v0.5.3`

发布日期：2026-09-06

`v0.5.3` 是 `v0.5.2` 的值班可见可靠性与安全补丁。

## 核心变化

- worker 挂了、lease 过期后，其他 worker 会接管 `RUNNING`/`LEASE_DEGRADED`/`RETRY_BACKOFF` 并继续拉流，不再让仪表盘显示 RUNNING 而 binlog 已经停了。新 worker 启动也不会把别人还在跑的任务在 meta 里写成 `STOPPED`。
- `FILE_POS`/`GTID` 追位点时，空闲 2s 不再把 lag 假显示成 0。只有 dump 位点确认到达 `SHOW MASTER STATUS` / `SHOW BINLOG STATUS` 才标 at-tip。`LATEST` 刚 start 已在 tip 的行为不变。
- 任务列表和 dashboard 任务页走 SQL 分页。`GetTask` 走主键。worker 认领循环不再整表 `SELECT`。
- 非 loopback 监听（包括默认 `:8080`）必须开 API 鉴权，并保护 `/api/*` 和 `/metrics`。本机 `127.0.0.1`/`localhost`/`::1` 仍可无鉴权做本地演示。
- 发布包打进 `config.example.yaml` 和 `config.production.example.yaml`。
- Quick Start、落地页和部署文档里的下载示例改为 `v0.5.3`。

## 升级影响

- `v0.5.3` 不需要 schema migration。
- 相对 `v0.5.2` 没有 API 契约变化。`GET /api/tasks` 仍是 `{items,total,limit,offset}`。
- 照抄 `:8080` 且不开鉴权会起不来。本地 demo 绑 loopback，或打开 `api.auth` 并保护 API/metrics。`config.example.yaml` 已绑 `127.0.0.1:8080`。
- 不加 `--encryption-key` 时，`source_json` 里的源库密码仍是明文。加密过的行以后启动必须带同一把 key。
- 集群里每个会读加密 `source_json` 的进程都要带同一把 `--encryption-key`。
