# Binlog Server v0.5.5 中文发布说明

> 对应版本：`v0.5.5`

发布日期：2026-09-21

`v0.5.5` 是 `v0.5.4` 的控制面观测补丁。

## 核心变化

- 按 id 读任务时，store 失败不再返回内存里的旧所有权抄本。没有就是 404，其它错误是 5xx。
- 源 lookup 和任务观测的 host 过滤共用 `SameSourceHost`。回环地址的不同写法是同一台源。
- 集群 overview、worker 任务计数、metrics 里的任务/主人，读的是全库 store 所有权抄本。不是当前过滤页，也不是启动时的内存名单。
- 控制台任务页只信 dashboard 这一次物化：页、汇总、按源计数。不再把缺 paging 字段当成旧包在本地再切一页。
- 任务列表刷新不再按行打 `/lease`。租约风险用任务上的主人、epoch 抄本。单任务查询仍走 `GET /api/tasks/{id}/lease`。
- 源 lookup 和集群观测读同一份 store 抄本。
- retry-upload E2E 从 Quay 拉 MinIO，不再用 Docker Hub 的 `minio/minio:latest`。
- Go 模块：validator `v10.30.4`、MySQL driver `v1.10.1`、migrate `v4.20.1`、`golang.org/x/time` `v0.16.0`。
- README 增加控制台、任务详情、Swagger 截图。
- Quick Start、落地页和部署文档里的下载示例改为 `v0.5.5`。

## 升级影响

- `v0.5.5` 不需要 schema migration。
- `GET /api/tasks` 仍是 `{items,total,limit,offset}`。Dashboard / summary 仍对过滤结果物化一次，再在进程内分页，不是再查一次 SQL `COUNT`。
- 单任务、集群 overview、workers 在 store 读失败时会失败，不再用过期内存快照冒充 200。把这些 200 当真相的客户端要能处理 5xx。
- 尽力上传语义不变：上传失败不打断拉流；手动重试仍走 `/api/tasks/{id}/files/retry-upload`。
