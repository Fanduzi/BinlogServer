# Binlog Server v0.5.29 中文发布说明

> 对应版本：`v0.5.29`

发布日期：2026-10-05

`v0.5.29` 在 `v0.5.28` 上，本地磁盘和桶可以把一份封存 binlog 保留不同的天数。已发布的 v0.5.28 包不能把这两边配成不同天数，仍使用一个截止时间。

## 核心变化

- `storage.retention_days` 仍是必填。范围仍是 1..3650。两个可选键是 `storage.local_retention_days` 和 `storage.bucket_retention_days`。省略或 `0` 等于 `retention_days`。这两个值为 0 的键不会出现在任务 JSON 里。有效本地天数和有效桶天数相等时，这一个相等的天数就是唯一的截止时间。只设置 `retention_days` 的任务是这种情况，把两个新键设成同一个有效天数也是这种情况。还在磁盘上的过期已上传分段会同时从对象、目录行和本地文件里删除，与 v0.5.28 相同。在这一个截止时间上，本地文件已经不在的目录行会留下。这条路径不读取 `sealed_at` 和 `uploaded_at`。
- 创建和更新比较的是有效天数。`POST /api/tasks` 和 `PUT /api/tasks/{id}` 拒绝桶窗口短于本地窗口。正文包含 `shorter than local retention`，并写出这两个数。创建返回 JSON，`code` 是 `INVALID_REQUEST`，这句话在 `error` 里。更新把这句话作为纯文本返回。两者都是 HTTP 400。两个窗口相等可以接受。非 0 的 `local_retention_days` 或 `bucket_retention_days` 超出 1..3650 是 HTTP 400。省略的键用 `retention_days` 作为那一边的窗口。`local_retention_days` 大于 `retention_days` 且省略 `bucket_retention_days` 时，会被拒绝。`local_retention_days` 小于 `retention_days` 且省略 `bucket_retention_days` 时，桶窗口仍是 `retention_days`。这个桶窗口更长，所以配了对象存储和目录时会走下面更长桶窗口的清理。省略 `local_retention_days` 并且把 `bucket_retention_days` 设得高于 `retention_days` 时也一样：本地窗口仍是 `retention_days`，桶窗口更长。
- 更长的桶窗口只在同时配了对象存储和目录（`meta_dsn`）时生效。已封存、`UPLOADED`、并且有对象键的分段，早于本地窗口、仍在桶窗口之内时，只删本地文件。对象和目录行留下。`file_path` 仍是目录里的路径。文件还在磁盘上时，两个窗口都看本地文件的修改时间。保留清理仍在复制循环打开 binlog 文件时执行。当前正在写的 open 分段留下。其它 open 分段也留下，保留不会为它们删对象。
- `GET /api/tasks/{id}/files` 的 `location` 是 `local`、`bucket` 或 `both`。`both` 表示本地文件和已上传对象都在。`local` 表示文件在本进程上，没有已上传对象。`bucket` 表示已封存的 `UPLOADED` 对象有对象键，而文件不在本进程上。本地文件不在、且本进程配了对象存储时，`GET /api/tasks/{id}/files/{name}` 流出这份对象的字节。`{name}` 是 basename。响应不会打开 `file_path`。`GET /api/tasks/{id}/replay` 对 `limit` 窗口和 `stop_datetime` 都是这样。`GET /api/tasks/{id}/replay/archive` 对同样的选择也是这样。回放的 `locations` 与 `paths` 顺序一致。值为 `bucket` 时，这条路径是目录里的 `file_path`，不在本进程上。先下载该分段或回放归档，再使用那些字节。下载之前不要把这条路径交给 `mysqlbinlog`。`stop_datetime` 的命令仍会打印目录路径。本进程没配对象存储时，磁盘上没有的文件仍是 404 `segment not found on this process`。
- 封存文件还在磁盘上时，两个窗口都看它的修改时间。修改时间早于桶窗口时，对象、目录行和本地文件一起删除。本地文件已经删掉之后，并且只有桶窗口长于本地窗口时，桶年龄用 `sealed_at`。`sealed_at` 为空时用 `uploaded_at`。两个都空时，对象和目录行留下。这个时间早于桶窗口之后，对象和目录行被删除。对象删除失败时，本地文件留下，`checksum` 保持原样（`match`、`mismatch` 或空），`last_error` 以 `OBJECT_PURGE_FAILED` 开头。下次打开文件会再删一次。分段仍在桶窗口内、只删本地文件时，不会删对象，也不会删目录行。
- 配了对象存储并且有目录时，早于本地窗口的已封存 `UPLOAD_FAILED` 或 `LOCAL_ONLY` 分段和目录行留在磁盘上。是否过期看本地文件的修改时间，对照本地窗口。复制继续跑。它不写 `last_error`，也不进入 `RETRY_BACKOFF`。`GET /api/tasks/{id}/events` 里，每个留下的文件有一条 `RETENTION_SKIPPED_NOT_UPLOADED`。消息写明文件名和它的 `upload_state`，例如 `mysql-bin.000003 upload_state=LOCAL_ONLY`。本进程还在跑时，再打开另一个 binlog 不会为同一个文件再追加这条事件。进程重启之后，下一次保留清理如果仍留下这个文件，会再追加一次这条事件。跑保留清理的进程在 `GET /metrics` 上暴露 `binlog_server_retention_blocked_files{task_id}`：最近一次成功的清理仍留下的这类过期文件数。后面某次清理把它们删掉后，这个数下降。重启之后，在下一次保留清理之前，它保持 0。只跑控制面的进程不做保留清理，所以那边的这个 gauge 保持 0。这条事件仍在 `GET /api/tasks/{id}/events`。已封存的 `UPLOAD_FAILED` 仍由后台补传捡起，也由 `POST /api/tasks/{id}/files/retry-upload` 捡起。两条路都可以把这一行变成 `UPLOADED`。变成 `UPLOADED` 之后，下一次保留清理按上面的窗口处理。
- `LOCAL_ONLY` 不会被后台补传捡起。手动补传也只选择已封存的 `UPLOAD_FAILED`，所以它也不会上传 `LOCAL_ONLY`。之后再配上对象存储，也不会上传这一行。没配置上传时，本地保留仍按本地窗口删除封存文件。目录行如果存在，会留下。不会写 `RETENTION_SKIPPED_NOT_UPLOADED`，gauge 保持 0。
- 没配 `meta_dsn` 的单机仍按本地年龄删除封存文件，包括从没进过桶的那一份。没有目录时，更长的 `bucket_retention_days` 不生效。上传仍在本地窗口把对象和本地文件一起删除。桶可能中断的时间长于本地保留时，不要把这种模式当成唯一副本。
- Console 任务详情显示有效的本地天数和有效的桶天数。省略的那一项在这里显示 `retention_days`。文件表显示 `location`。API 的值是 `local`、`bucket` 或 `both`。英文 Console 显示这几个词。中文 Console 显示「本地」「桶」或「本地和桶」。`location` 为 `bucket` 的分段会提示这条路径不在这台机器上：先下载该分段或回放集，下载之前不要把这条路径交给 `mysqlbinlog`。这个 Console 在普通 `go build` 提供的嵌入包里。

## 升级影响

- `v0.5.29` 不需要 schema migration。迁移仍只有 `000001_init_schema`。新键写在已有的任务存储 JSON 里。
- `storage.retention_days` 没有变化。`cluster.failover_policy` 仍然不是开关。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
- 已经只设置 `retention_days` 的任务保持 v0.5.28 的清理。有效桶窗口长于有效本地窗口，并且本进程配了对象存储和 `meta_dsn` 时，才按更长的桶窗口清理。
