# Binlog Server v0.5.6 中文发布说明

> 对应版本：`v0.5.6`

发布日期：2026-10-02

`v0.5.6` 是 `v0.5.5` 的控制台、生产 fail-closed 和 dashboard 规模补丁。

## 核心变化

- `v0.5.5` 嵌入的 Console 挂不上。入口包的 import 列表多了一个 `}`，Chrome 抛 `SyntaxError: Unexpected token ','`，页面壳不会挂上。按干净的 UI 构建重打后可以挂上。`scripts/check-ui-bundle.sh` 对 `index.html` 引用的 JS 跑 `node --check --input-type=module`，CI 和 release 都会跑。对 `.js` 路径直接 `node --check` 会按 CommonJS 解析，抓不到这个错误。
- `PRODUCTION=true` 且 `--encryption-key` 为空时，进程在监听前返回。`api.auth.enabled=true` 时，`/ui/*` 和 `/swagger/*` 走同一套鉴权中间件。`/healthz` 仍开放。控制台锁跟着 `api.auth.enabled`，不是 `protect_api`。
- `GET /api/dashboard` 和 `GET /api/summary` 用 SQL `GROUP BY` 计状态和按源汇总，任务行用 `LIMIT/OFFSET` 分页。延迟分类只读 RUNNING 任务 id。不再把 `Limit=0` 当成全表扫描。`total`、`summary.total`、按源 `task_count` 仍是同一过滤集。
- `scripts/failover-dogfood.sh` 和 verify-binlog-server 的 failover-lease 技能，用一个 meta MySQL 证明双 worker 租约接管。租约状态机没有改。
- 仓库内的 verify-binlog-server Cursor 技能用已发布二进制走 HTTP API 和嵌入 Console。
- Go 模块：validator `v10.30.5`。
- Quick Start、落地页和部署文档里的下载示例改为 `v0.5.6`。

## 升级影响

- `v0.5.6` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- `PRODUCTION=true` 必须带非空 `--encryption-key`，否则进程不监听。生产模式之外，空 key 仍会加载已有明文行。
- `api.auth.enabled=true` 时，浏览器直接打开 `/ui/` 或 `/swagger/` 会 401，直到代理或客户端带上同一个 bearer token 或 API key。loopback 且鉴权关闭的演示仍是开放控制台。`/healthz` 不鉴权。
- `GET /api/tasks` 仍是 `{items,total,limit,offset}`。Dashboard / summary 的计数是这条过滤集上的 SQL 聚合，不再在进程里扫每一行任务。
- 租约归属、接管事件和认领路径相对 `v0.5.5` 没有变化。
