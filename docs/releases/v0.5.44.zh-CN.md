# Binlog Server v0.5.44 中文发布说明

> 对应版本：`v0.5.44`

发布日期：2026-10-06

迁移 `000003_task_desired_and_retry_budget` 给 `backup_tasks` 增加六列，都是 `NOT NULL` 且带默认值：`desired_run`、`spec_revision`、`applied_spec_revision`、`failed_spec_revision`、`retry_attempt`、`consecutive_source_failures`。已有行会回填。`RUNNING`、`STARTING`、`RETRY_BACKOFF`、`LEASE_DEGRADED`、`REBUILDING_FILE` 的 `desired_run` 写成 `RUN`。`CREATED`、`STOPPING`、`STOPPED`、`FAILED` 写成 `STOP`。修订号和计数器都是 0。正在跑的进程不读、不写这些列。这是 ADR 0005 的第 2 步，一共 9 步。`minRequiredSchemaVersion` 仍是 2。v0.5.44 在 schema 2 或 schema 3 上都能启动。v0.5.43 在 schema 3 上继续跑。没有新的配置项。运行时行为不变。跟踪为 PR #236。

## 核心变化

- 迁移 `000003_task_desired_and_retry_budget` 给 `backup_tasks` 增加六列，都是 `NOT NULL` 且带默认值：`desired_run`、`spec_revision`、`applied_spec_revision`、`failed_spec_revision`、`retry_attempt`、`consecutive_source_failures`。旧二进制的插入不列出这些列。每列都有默认值，所以这次插入仍然能写进去。
- 回填把 `RUNNING`、`STARTING`、`RETRY_BACKOFF`、`LEASE_DEGRADED`、`REBUILDING_FILE` 的 `desired_run` 写成 `RUN`。`CREATED`、`STOPPING`、`STOPPED`、`FAILED` 写成 `STOP`。`spec_revision`、`applied_spec_revision`、`failed_spec_revision`、`retry_attempt`、`consecutive_source_failures` 都是 0。`FAILED` 行的 `failed_spec_revision` 保持 0。
- 运行时不读、不写这些列。ADR 0005（`docs/adr/0005-single-task-authority-and-segment-catalog.md`）第 2 步只做这次迁移，一共 9 步。`minRequiredSchemaVersion` 仍是 2。v0.5.44 在 schema 2 或 schema 3 上都能启动。v0.5.43 在库升到 schema 3 之后继续跑。
- 没有新的配置项。任务状态、重试、租约和拉流与 v0.5.43 相同。

## 升级影响

进程保持运行时执行 `./migrate up`。这次迁移不需要重启。这一点在 v0.5.43 仍在跑的时候核对过。确认 `SELECT version, dirty FROM schema_migrations` 是 `(3, 0)`。`SHOW COLUMNS FROM backup_tasks` 列出 `desired_run`、`spec_revision`、`applied_spec_revision`、`failed_spec_revision`、`retry_attempt`、`consecutive_source_failures`。然后按任意顺序替换二进制。v0.5.44 在 schema 2 或 schema 3 上都能跑。v0.5.43 在 schema 3 上继续跑。`minRequiredSchemaVersion` 仍是 2。`migrations/` 是 `000001`、`000002` 和 `000003`。

建议现在就做这次迁移。ADR 0005 下一步（第 3 步，持久化重试预算）会把 `minRequiredSchemaVersion` 提到 3。要求 schema 3 的二进制在 schema 2 上不会启动。

还在 schema 1 上的库，要先迁移，当前二进制才会启动。按 [v0.5.34 升级说明](v0.5.34.zh-CN.md)：停掉这个元数据库上的每一台 binlog-server，执行 `./migrate up`，然后只启动 v0.5.34 或更新的二进制。这一版可以在线做的是从 schema 2 升到 schema 3。

回滚是 `./migrate down --steps 1`。`schema_migrations` 回到版本 2，只删掉这六列。`backup_tasks` 和 `binlog_files` 的行数不变。

没有新的配置项。运行时行为不变。

## 已知行为

下面这些仍开着。#239、#189、#193、#205、#224 在这一版之前就有。

- 同一串失败里重启两次，最多要到第 14 次失败才进入 `FAILED`。认领写下的 `TASK_STARTED` 和操作员 Start 分不出来，所以第二次重启只留下上一次认领之后的失败。重启之后退避从 1 秒重新起跳。结构性修复是 ADR 0005 第 3 步，把重试预算做成持久化列。跟踪为 #239。
- 故障切换后，同名封存段的 `end_pos` 写成 0。跟踪为 #189。
- 停止期间改密码再 Start 后，源库可能残留多余 Binlog Dump 连接。跟踪为 #193。
- GTID 启动或 1236 回退后写入无 CRC 的人工 Rotate，校验失败，并产生多余的 `task-N.binlog`。跟踪为 #205。
- 接管下载 `UPLOADED` 对象时进程崩溃，`.takeover-*` 临时文件会一直留在磁盘上。重启、重试成功后都不清理。跟踪为 #224。
