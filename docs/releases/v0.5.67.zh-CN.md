# Binlog Server v0.5.67 中文发布说明

> 对应版本：`v0.5.67`

发布日期：2026-10-15

v0.5.67 让 standalone 重启后自动恢复任务，任务记录加密落盘（#385，ADR 0010）。同时合入 ADR 0009 健康评估器第二阶段（P2-1..P2-4），**默认 `off`**；修复封存段被截断（#381）、FAILED 状态丢失（#389），以及切换源或大事务后的续传和 checkpoint 问题（#391）。新增迁移 `000009`，只增不改、可选：`minRequiredSchemaVersion` 仍是 6，地板仍是 v0.5.51。

**升级 standalone 前请先读升级须知**：在升级重启之前配置任务密钥；之后每个从 v0.5.66 带过来的任务都要 adopt 一次（批量：`scripts/adopt-leftovers.sh`）。

## 升级须知

### `/api/health` 可能返回 503

有打开的 CRITICAL finding 时，`GET /api/health` 返回 **503 `{"status":"degraded","reasons":[...]}`**，否则返回 200 `{"status":"ok"}`。结果按内存中的 finding 状态计算，所以即使 `data_dir` 写满、finding 无法落盘，也照样会降级（见下文 `FINDINGS_PERSIST_FAILED`）。

**存活探针必须用 `GET /healthz`**（不变，200 `ok`）。探针若指向 `/api/health`，任何 CRITICAL finding 都会导致进程被重启。`/api/health` 只用于告警或就绪检查。

### standalone：升级重启之前配置密钥，之后每个任务 adopt 一次

`standalone.task_records` 默认 `on`。standalone（无 `meta_dsn`）**若未配置密钥，会打开 CRITICAL `TASK_RECORDS_FAILED/key_missing`，`/api/health` 显示 degraded。** 任务只运行到下一次重启为止；没有密钥时的任何一次重启都会把所有任务变成 STOPPED 的遗留目录。

**从 v0.5.66 升级的 standalone，不管有没有密钥，所有任务都会变成遗留目录**（v0.5.66 不保存记录）。升级重启后，每个任务显示为 STOPPED、source 为空，复制停止，并打开 CRITICAL `TASK_UNADOPTED`；任何 `health.evaluator` 模式下它都会让 `/api/health` 降级（#399）。**每个任务目录都必须 adopt 一次**，之后重启才会自动恢复。

升级步骤：

1. **停 v0.5.66 之前**，用新二进制生成密钥（旧服务还在运行也可以）。命令以 `0600` 写入文件，路径已存在时拒绝覆盖，只输出路径和 key id：
   ```bash
   ./binlog-server-v0.5.67 task-key generate --out /etc/binlog-server/task.key
   ```
   文件放在 `data_dir` 之外，并单独备份。没有密钥就读不了 `.tasks.enc`。
2. **重启之前**，在配置里指定密钥，**任选其一**：
   - **密钥文件（推荐）**：配置 `standalone.task_key_file: /etc/binlog-server/task.key`，或设环境变量 `BINLOG_SERVER_STANDALONE_TASK_KEY_FILE`。必须是普通文件，权限 `0600` 或 `0400`；权限更宽会拒绝该密钥（`TASK_RECORDS_FAILED/key_invalid`），不会替你改权限。
   - **环境变量**：`BINLOG_SERVER_TASK_KEY=<base64 或 64 位十六进制，32 字节>`，适合容器 secret。进程读取后立即 unset 该变量。仍推荐用文件，因为运行中进程的环境变量对同一用户和 root 可见。
   - 不接受写在 YAML 文件里的密钥。
3. 替换二进制并重启。不会出现 `key_missing`，每个任务目录都会打开 `TASK_UNADOPTED`。
4. **adopt 每个目录。** adopt 需要源（含密码）**和 `cluster_key`**，缺 `cluster_key` 时 API 返回 400 `cluster_key is required`；`name` 和 `storage` 可选。批量 adopt 用 release 压缩包里自带的 `scripts/adopt-leftovers.sh`（需要 `curl` 和 `jq`）：
   ```bash
   scripts/adopt-leftovers.sh --api http://127.0.0.1:8080              # 列出遗留目录并输出映射模板
   # 为每个 id 填写 name、cluster_key、source；文件含密码，chmod 600
   scripts/adopt-leftovers.sh --api http://127.0.0.1:8080 --map adopt-map.json --start
   ```
   脚本对每个打开 `TASK_UNADOPTED` 的任务执行 adopt，加 `--start` 时同时启动；仍有目录未 adopt 时以非零状态退出。鉴权：`BINLOG_SERVER_API_KEY` 或 `BINLOG_SERVER_BEARER_TOKEN`。单个目录也可以手工 adopt：`POST /api/tasks/{id}/adopt`，body 为 `{"name":"...","cluster_key":"...","source":{...}}`，然后 `POST /api/tasks/{id}/start`。
5. 确认 `/api/findings` 里没有 `TASK_UNADOPTED`、`/api/health` 为 200。此后每次重启都会自动恢复任务。

如果先跳过了密钥、之后才加上，期间建的每个任务在加密钥的那次重启后都是遗留目录，会打开 `TASK_UNADOPTED`；按第 4 步 adopt。

不想用任务记录可设 `standalone.task_records: off`，行为同 v0.5.66：任务只存内存，每次重启后遗留目录都需要 adopt；遗留目录仍会打开 `TASK_UNADOPTED`。

其他需要知道的 standalone 变化：

- **一个 `data_dir` 只允许一个进程。** standalone 启动时对 `{data_dir}/.tasks.lock` 取独占 `flock`。同一 `data_dir` 上的第二个进程以非零状态退出，并给出锁文件和持有者的 pid。`flock` 保护不了 NFS 上的 `data_dir`。
- **拒绝改为 503。** 记录无法读取（密钥错误、文件损坏）或保存失败时，Create/Adopt/Update/Start 返回 **503 `TASK_RECORDS_UNAVAILABLE`**（原来是 500，Start 是 400），且不覆盖文件。Stop/Delete 从不被拒绝：保存失败时在内存中生效，打开 `TASK_RECORDS_FAILED/write`，每 30 s 重试保存。
- **密钥轮换**：把旧密钥设为 `standalone.task_key_previous_file`（或 `BINLOG_SERVER_TASK_KEY_PREVIOUS`），新密钥设为当前密钥，然后重启；启动时文件改用新密钥重新加密。

### 新配置项

| 配置项 | 默认 | 作用 |
|---|---|---|
| `standalone.task_records` | `on` | standalone 加密任务记录与自动恢复（`on` / `off`） |
| `standalone.task_key_file` | `""` | 密钥文件，`0600`/`0400`（环境变量 `BINLOG_SERVER_STANDALONE_TASK_KEY_FILE`）；也可用 `BINLOG_SERVER_TASK_KEY` |
| `standalone.task_key_previous_file` | `""` | 轮换期间的旧密钥；也可用 `BINLOG_SERVER_TASK_KEY_PREVIOUS` |
| `health.evaluator` | `off` | 第二阶段健康评估器：`off` / `shadow` / `on` |
| `health.sweep_interval_sec` | `60` | 评估器 sweep 间隔 |
| `health.rehash_bytes_per_sec` | `4194304` | 封存段 sha256 复核的全局字节预算 |
| `health.unreachable_after_sec` | `90` | `SOURCE_UNREACHABLE` 阈值 |
| `health.unreachable_after_task_sec` | — | 按任务覆盖上一项（任务 id 到秒数的映射） |
| `health.signal_stale_after_sec` | `86400` | 信号多久没有更新算作过期 |

### 迁移与上线

- 迁移 `000009`（`task_findings` 加健康列，另加 `task_health`、`finding_transitions`、`notify_cursor`、`rehash_cursor`、`task_mutes`）只增不改、可选。只有带元数据 DSN 且 `health.evaluator` 为 `shadow`/`on` 时才需要；standalone 改写 `{data_dir}/.health.json`。建议执行 `./migrate up`。
- 集群：所有节点都升级到 v0.5.67 之前保持 `health.evaluator: off`，之后先切 `shadow`，再切 `on`。本版本在有旧节点时没有自动回退，滚动升级期间不要切换。
- **回滚到 v0.5.66**：
  - meta：在 schema 9 上可以正常运行。
  - standalone：v0.5.66 忽略 `.tasks.enc` 和 `.tasks.lock`。也就是不会自动恢复（每个任务又成为遗留目录，需要 adopt），也没有单写者保护：没有任何机制阻止两个进程使用同一个 `data_dir`。再升级回 v0.5.67 会按记录恢复。
- v0.5.66 的说明仍然有效。从 v0.5.61 或更早版本升级，请先读 [v0.5.62 说明](release-notes-v0.5.62.md)。

## 亮点

- **standalone 加密任务记录与自动恢复（#385，ADR 0010；PR #393、#395）。**
  - 保存的内容：任务规格（含源库密码）、期望状态、终态失败、id 序号、删除墓碑，存于 `{data_dir}/.tasks.enc`。AES-256-GCM 加密，信封带版本和 key id，以 `0600` 原子写入。
  - 不保存的内容：位置。续传位置总是按 adopt 规则从磁盘上的字节计算。磁盘上一个段都没有的 LATEST 任务按 LATEST 续跑，并记 `TASK_RESUMED_AT_LATEST`。GTID 任务续传集合 = 起始集 ∪ 各封存段的 GTID ∪ 打开段尾（MySQL）。
  - 新 CRITICAL finding `TASK_RECORDS_FAILED`（`_cluster`；subject `key_missing`、`key_invalid`、`wrong_key`、`corrupt`、`write`）。
  - 文件无法读取时：不恢复、拒绝写入、文件保持不动。
- **磁盘写满时 finding 不丢。** 健康文件或 findings 文件写不进去（例如 ENOSPC）时，finding 由内存提供给 `/api/findings`，并计入 `/api/health`。合成的 CRITICAL `FINDINGS_PERSIST_FAILED` 指明失败的写入；它从不落盘，写入恢复后自动关闭。已在 30 MB tmpfs 上验证。
- **健康评估器第二阶段（ADR 0009，P2-1..P2-4；PR #375、#376、#377、#378、#380、#383），默认 `off`。**
  - P2-1：纯健康类型、kind 注册表与 reconcile，处理 MySQL/MariaDB 的 GTID 集合；#377 让 UPDATE/DOWNGRADE 需要所有 scope，并支持十六进制 uuid 和带 tag 的 GTID。
  - P2-2：迁移 `000009` 与健康存储（MySQL 及 standalone 文件存储），带 fence。
  - P2-3：评估器与 rehasher。rehasher 按封存校验和复核封存段，与 `/window` 共用带 CRC 校验的可读性判断，并对账目录与磁盘。
  - P2-4：信号类 kind。在 socket 层测量的同一个源活性时钟同时驱动 `DUMP_STALLED`（静默 ≥ 45 s）和新增的 `SOURCE_UNREACHABLE`（≥ `health.unreachable_after_sec`），STARTING/RETRY_BACKOFF 期间同样计时。
  - `on` 时由评估器接管 Managed kind，条件消失即关闭；`shadow` 只评估并记日志。
- **standalone 遗留目录 finding（#388、#399）。** 任何 `health.evaluator` 模式下，只有 `data_dir` 知道的目录都会打开 CRITICAL `TASK_UNADOPTED`，detail 里给出 adopt 调用，`/api/health` 降级；评估器 off 时走旧 sink。adopt 后关闭；把目录移出 `data_dir` 也会关闭。`scripts/adopt-leftovers.sh` 可以批量 adopt。

## 修复

- **#381（PR #384）**：被截到 0 字节、截在 magic 或事件头中间、或比封存时短的封存段，过去被当作完整段读取。现在判为不可读：打开 `SEGMENT_UNREADABLE`，`/window`、`/replay` 和链检查都在它之前停下并说明原因。
- **#389（PR #390）**：在 run 写入 FAILED 和退出之间到达的 `GET`，会把 FAILED 变成无声的 STOPPED。任务自己的 FAILED 行不再被当作远程 Stop。
- **#391**：
  - PR #394：切换源后，续传集合包含所有封存段的 GTID，而不只是落后的 checkpoint 加打开段尾。过去这些 GTID 会被再次拉取、重复存储，并报为 `SEGMENT_OVERLAP`。
  - PR #396：checkpoint 和 OPEN 目录行改在事务边界写入，200 ms 内的提交合并写，不再每个事件写一次。3 MB、约 2 万个事件的事务不再需要约 2.8 万次元数据写入而卡住。
- standalone 下 `/api/findings` 列出评估器管理的 `_cluster` finding。

## 已知行为

- 记录为 RUN 的任务目录在停机时被删除或移出 `data_dir`，会从操作员起点重新拉取，且没有 finding。要退役目录，请先 Delete 任务。相应的 finding 见 #397。
- `.tasks.lock` 的 `flock` 保护不了 NFS 上的 `data_dir`。
- #365–#368、#312、#341–#345、#352、#353、#360、#363（P3）仍未关闭。
