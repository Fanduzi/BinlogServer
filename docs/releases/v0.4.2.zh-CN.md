# Binlog Server v0.4.2 中文发布说明

> 对应版本：`v0.4.2`

`v0.4.2` 是一次面向 v0.4.1 值班实测的补丁：修复 MariaDB 启动失败、创建任务 400 仍落库并改成 LATEST、不友好的失败路径，以及第一公里安装文档。

## 核心变化

- `POST /api/tasks` 整包校验通过后才落库。HTTP 400 返回 JSON `{"error","code"}`，不会留下一条 `LATEST` 任务。
- `flavor=mariadb` 不再因为 `empty server_uuid` 失败。身份使用 `server_id` + `gtid_domain_id`。未开 binlog 以 `SOURCE_LOG_BIN_OFF` 失败。
- ERROR 1045 映射为 `SOURCE_ACCESS_DENIED` 并进入 `FAILED`，不再无限 `RETRY_BACKOFF`。改完密码后可以再次 `POST /start`。
- 已经跟到 tip 的静默主库不再被标成十几小时 `DELAYED`。空闲等待时 lag 为 `0` / `NORMAL`。heartbeat 事件不会写入备份文件。
- 端口占用等 bind 失败不再刷 cobra `Usage`。`GET /api/health` 返回 `{"status":"ok"}`，`GET /healthz` 保持不变。
- Quick Start 改为下载 tarball、校验 checksum、解压、`./binlog-server`。`go run` 移到 Development。

## 升级影响

- `v0.4.2` 无 schema 变更，不需要执行数据库迁移。
- `POST /api/tasks` 现在要求 `source.password`。漏写密码会从 201 变成 400。
- `POST /api/tasks/{id}/start` 仍是 `204 No Content`。
- 未配置 `meta_dsn` 的 standalone 控制面仍在内存。要重启可恢复，以及运行中 `GET /checkpoint` / `GET /files`，请配置 `meta_dsn`。`storage.dir` 仍被忽略，路径固定 `{data_dir}/{task_id}/`。

## 运维收益

- 值班可以按 GitHub Release 安装，不必先装 Go。
- 开了 binlog 的 MariaDB 源库可以 START，而不是卡在 `empty server_uuid`。
- 错误的 GTID/FILE_POS 创建不会再留下一条一点 Start 就从最新点拉的任务。
- 错误密码会失败并停住，修好后可以再启动；安静主库不再被当成严重延迟。
