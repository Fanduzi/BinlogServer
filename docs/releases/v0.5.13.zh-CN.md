# Binlog Server v0.5.13 中文发布说明

> 对应版本：`v0.5.13`

发布日期：2026-10-03

`v0.5.13` 是 `v0.5.11` 已有 adopt API 上的 Console 表面。`v0.5.11` 已经接受 `POST /api/tasks/{id}/adopt`。这一版从 Console 提交同一次请求。已发布的 v0.5.12 压缩包仍然没有 Console adopt 按钮。API 没有变化。没有 schema migration，没有新的配置键。

## 核心变化

- standalone 没配 `meta_dsn`：遗留目录会列出。中文 Console 里，这一行详情操作是 认领、启动、停止、删除。没有 编辑。已经有源库账号的任务显示 编辑、启动、停止、删除，没有 认领。认领通过已有的 `POST /api/tasks/{id}/adopt` 提交 `cluster_key` 和 source。启动模式留在默认（最高分段末尾）时不发送覆盖。成功提示是 任务已认领。任务保持 已停止，显示源库和 cluster key，不显示密码，不会开始复制。原来的 启动 再把它拉起来。本次 tip `39981ead` 的试用（版本串 `v0.0.0-20261003150852-39981ead3fd5`，不是已发布的 v0.5.12 压缩包）：同一目录出现下一段 epoch `mysql-bin.000005.open.e2`，更早分段的大小不变。
- 配了 `meta_dsn` 时，遗留目录不会列出。Console 表格是空的。id `99` 和 `42` 不出现，也没有 认领。`POST /api/tasks/99/adopt` 返回 404，正文是 `task not found`。`backup_tasks` 仍是 0。adopt 不会从目录创建任务。
- API 没有变化。不需要 schema migration。没有新的配置键。这一版的 adopt 是 `v0.5.11` 已有 API 上的 Console 表面。已发布的 v0.5.12 压缩包仍然没有 Console adopt 按钮。
- Quick Start、落地页、部署文档、配置模板和 workers API 示例里的版本钉在 `v0.5.13`。

## 升级影响

- `v0.5.13` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 配置键没有变化。`PRODUCTION=true` 仍要求非空 `--encryption-key`。API 与 `v0.5.11` 相同。
- standalone 没配 `meta_dsn`：遗留目录会列出。中文 Console 里，这一行详情操作是 认领、启动、停止、删除，没有 编辑。已经有源库账号的任务显示 编辑、启动、停止、删除，没有 认领。认领通过已有的 `POST /api/tasks/{id}/adopt` 提交 `cluster_key` 和 source。启动模式留在默认（最高分段末尾）时不发送覆盖。成功提示是 任务已认领。任务保持 已停止，显示源库和 cluster key，不显示密码，不会开始复制。原来的 启动 再把它拉起来。试用：版本串 `v0.0.0-20261003150852-39981ead3fd5`（tip `39981ead`，不是已发布的 v0.5.12 压缩包），同一目录出现 `mysql-bin.000005.open.e2`，更早分段的大小不变。
