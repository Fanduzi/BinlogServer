# Binlog Server v0.5.20 中文发布说明

> 对应版本：`v0.5.20`

发布日期：2026-10-04

`v0.5.20` 在 `v0.5.19` 上扩展单分段下载。`{data_dir}/{id}/{name}` 不在本进程上时，DBA 仍可以下载已经 `UPLOADED` 的封存分段，走同一条已认证 API 和 Console 下载。已发布的 v0.5.19 压缩包对这个缺失的本地文件返回 404 `segment not found on this process`，不会读对象存储。

## 核心变化

- `GET /api/tasks/{id}/files/{name}` 仍先打开 `{data_dir}/{id}/{name}` 下的本地文件，包括任务处于 `RUNNING` 或 `STOPPED` 时名为 `*.open.e*` 的 open 分段。本地文件不存在时，封存目录行的 `upload_state` 为 `UPLOADED` 且 `object_key` 非空，则从已经配置用于上传的对象存储流式读取。`{name}` 是这个 basename，不是 object key。`Content-Type` 是 `application/octet-stream`。`Content-Disposition` 使用这个 basename。对象的正文长度是打开对象时的大小。本地文件的正文长度仍是打开时的文件大小。本地文件优先于对象。Console 下载走同一条路由，浏览器不会打开桶。
- `LOCAL_ONLY` 行、`UPLOAD_FAILED` 行、空的 `object_key`、没有本地文件的 open 分段，以及本进程没有配置对象存储，仍返回 404 `segment not found on this process`。名字含 `/`、`\` 或 `..` 仍返回 400 `invalid segment name`。任务不存在仍返回 404 `task not found`。响应不跟随 catalog `file_path`，也不会为 open 分段从对象存储编造字节。
- `GET /api/tasks/{id}/files` 和 `GET /api/tasks/{id}/replay` 没有变化。文件列表仍列出每一个文件名。回放仍是每个源序号一条路径；同一序号既有封存名又有 `.open.e*` 时，路径是 epoch 最大的 open 分段，并保留 `.open.e*` 后缀。

## 升级影响

- `v0.5.20` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 没有新的配置键。下载仍是 `v0.5.19` 那条只读 API。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
