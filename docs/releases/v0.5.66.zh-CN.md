# Binlog Server v0.5.66 中文发布说明

> 对应版本：`v0.5.66`

发布日期：2026-10-15

v0.5.66 能在运行时发现任务目录里同一个封存源文件存了两份（#370，PR #372；ADR 0009 不变量 I4）。没有 API 变化，没有新配置项，没有新迁移。`minRequiredSchemaVersion` 仍是 6，地板仍是 v0.5.51。BinlogServerQA 对 main `2c04c56513b5264b396e8c48b73e058ecc102d0e` 的 tip dogfood 通过，没有新发现。

## 亮点

- **重复封存段：`SEGMENT_OVERLAP`（PR #372、#370）。** 任务目录里同一封存源文件有两份本地副本时（例如 `mysql-bin.000006` 与 `mysql-bin.000006.sealed.e3`）：
  - 打开 CRITICAL `SEGMENT_OVERLAP` finding，指明后一个副本；
  - 任务显示 `storage_alert` `STORAGE_INCONSISTENT`；
  - `GET /window` 不再连续，断点指向该副本；
  - `/replay` 和 `/replay/archive` 截到两个副本之前并给出警告，`mysqlbinlog` 不会读到零填充副本，也不会重复应用同一批事务。
  - 半截副本仍报 `SEGMENT_UNREADABLE`。相互续接的 epoch（回切或拆分续写）不算重叠；干净目录的 replay 结果与 v0.5.65 一致。

## 升级说明

- 替换二进制并重启。没有迁移，没有配置变化。`000007`、`000008` 仍可选，仍建议 `./migrate up` 到 8。
- 升级后检查每个任务有没有 `storage_alert` 和 `SEGMENT_OVERLAP`。有的话说明目录里有重复副本：比对两份文件，保留与源一致的那份，把另一份移出任务目录。移走后告警、window 断点和 replay 截断都会消失。
- v0.5.65 的规则仍然有效，包括 MariaDB 11.4+ 重新全量备份的建议。从 v0.5.61 或更早升级，请先读 [v0.5.62 说明](v0.5.62.zh-CN.md)。

## 已知行为

- 与 `SEGMENT_UNREADABLE` 一样，移走副本后 `SEGMENT_OVERLAP` finding 不会自动关闭（告警、断点和截断会消失）。计划由 ADR 0009 第 2 阶段处理。
- #365–#368、#312、#341–#345、#352、#353、#360、#363（P3）仍未关闭。
