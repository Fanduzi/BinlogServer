# Binlog Server v0.5.81

Release date: 2026-10-27

v0.5.81 makes HTTP shutdown fast and makes the `-race` gate deterministic (#535, superseding #532). On shutdown, the control plane and the worker health server now close idle keep-alive connections and connections that never sent a request, instead of waiting out the 5 s HTTP shutdown budget on them. The `race-and-vet` CI job no longer skips any test, and the cold health evaluator walk is bounded in CI by the filesystem syscalls and bytes the kernel records for one pass. Fixes #439, #490, #504, #526 and #534. No new migration (schema up to 10, `minRequiredSchemaVersion` still 6), no new config keys, and the upgrade floor stays v0.5.51. The production-readiness checklist stays at MET 20 / PARTIAL 6 / NOT MET 9; G1 no longer lists #439 as a blocker.

## Upgrade Notes

- **No migration, no config change.** The highest schema is still 10 and `minRequiredSchemaVersion` is still 6. From v0.5.80, replace the binary. The v0.5.80 notes still apply when upgrading from v0.5.79 or earlier, including the `upload.use_ssl` default change.
- **Shutdown is faster with idle clients.** A client that holds an idle keep-alive connection, or a connection that has not sent a request, no longer delays `SIGTERM` by up to 5 s; Tip QA measured 0.01 s with idle keep-alives open. Such a client sees its connection closed during shutdown and must reconnect, as with any restart. A request that is still being served still gets up to 5 s to finish.
- **Rollback.** v0.5.80 runs on the same schema and the same config, so the binary can be rolled back. It only brings back the slower shutdown with idle connections.

## Fixes

- **HTTP shutdown (#535):** `server.Shutdown` left a connection that had not sent a request alone for 5 s, the whole HTTP shutdown budget. Shutdown now closes idle keep-alives and never-requested connections first, and the ConnState hook closes a connection that becomes new or idle after the close has started. In-flight requests keep their 5 s.
- **#439:** `TestApp_ProductionAuthProtectsRealRoutes` failed now and then under `-race` because the app did not shut down in time. The test now uses its own HTTP client with keep-alives on and a `t.TempDir()` data directory, so the production close is what keeps shutdown within its 2 s bound.
- **#490:** `TestFailurePathMatrixMetaOutage` and `TestOpenEpochENOENTAfterTakeoverDoesNotFail` were unstable under `-race`. The tests now wait for an observable result (for example, the finding sink finishing its write) instead of wall clocks.
- **#504:** `TestOpenReplayArchive_MissingOpenSegmentIsNotOnProcess` and the 1500-segment evaluator test were unstable under load. The evaluator test is now `TestEvaluator_1500SegmentsNearLinear`, which counts walk operations instead of timing the pass (2 s hang guard only).
- **#526:** `TestTaskRecords_StopAndDeleteApplyWhenSaveFails` was unstable in the full `-race` suite.
- **#534:** the replay archive temp file count in `internal/api` counted the process temp directory and collided with `internal/replication` running in parallel. Replay archive temps now live in an unexported directory inside the tasks package, and the test counts only that directory.

## CI

- `race-and-vet` runs `go test -race -count=1 ./...` with no `-skip` list. The six tests it used to skip (#439, #490, #504, #526) run there again.
- `TestEvaluator_SyscallWalkNearLinear` (Linux) re-executes the test binary under `strace -f -ttt` for a 150-segment and a 1500-segment cold evaluator pass, and counts the filesystem syscalls plus the bytes returned by `getdents64`, `read`, `pread64` and `readv`. Each pass must stay within 231 syscalls per segment plus 16 and 1506 bytes per segment plus 4096, and each 1500-segment total within 10.5 times the 150-segment total (measured 23140 / 231117 syscalls and 150467 / 1500475 bytes). The `go test` jobs in CI and in the release workflow install strace; a missing strace fails the test.
- `TestEvaluator_1500SegmentsNearLinear` counts in-process walk operations at the new `internal/binlog` walk seam (at most 36 per segment plus 16, measured 3612 / 36012). It is the fast local signal.
- Out of scope for these bounds: pure CPU or sleep per segment, name-only loops, and linear reads through `mmap`, `sendfile` or `statx`, which add no bytes.

## Known issues

- **#541 (P3):** test gaps from the #536 QA (upload TLS classifier mutations). The behaviour is correct today; these are missing guards, not known bugs.
- **#540 (P3):** `TestStopStartUnderPollKeepsOpenEpoch` (`internal/replication`) fails now and then under heavy `-race` load. Test-only.
- **#386 (P3):** `internal/tasks` tests can be flaky under fault load. No test is named; it stays open.
- **#510:** a non-owner node can keep listing a closed `SEGMENT_MISSING` in `/api/health` and `/api/findings` (and return 503). Check the owner's `/api/health` before acting on a non-owner's 503.
- **#473 (P1):** with per-node storage, a takeover after the owner pauses past the TTL hits `SEGMENT_NOT_ON_WORKER` and writes FAILED / desired STOP. ADR 0011 PR-4 is in progress.
- **#462 (P1):** the cluster silent gap is covered by unit tests; full closure comes with ADR 0011 PR-5.
- **#513 (P2):** after a takeover, a resumed old owner can write FAILED onto the new owner's task row; backup stops until an operator Start.
- **#539:** task start/stop opens more connections to the source than needed.
- **#514**, **#512**, **#494**, **#500**, **#502**, **#503** (P3) are still open, as are **#487**, **#488**, **#451**, **#452**, **#455**, **#456**, **#446**, **#437** and **#438**. `/api/findings` has no read timeout yet (P2-7). The verifier does not run in cluster mode (A4 PARTIAL).
