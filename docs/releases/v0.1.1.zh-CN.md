# Binlog Server v0.1.1 中文发布说明

> 对应版本：`v0.1.1`
> 文档定位：仓库内中文版 release note，可作为 GitHub Release 的中文补充阅读材料

`v0.1.1` 是一次小版本更新，重点聚焦 Web UI 的运维控制台体验和前端验收能力补齐。

## Highlights

- Web UI 调整为更偏运维控制台的交互结构，优先突出异常、失败、延迟等高优先级信息
- 任务列表减少行内操作噪声，把主要处置动作收敛到详情抽屉
- 认证失效 (`401`) 场景改为页内中文引导，并直接拉起设置对话框完成恢复
- 补回上传失败文件的重试上传入口，并在任务详情中完成刷新闭环
- 新增基于 Playwright 的最小 E2E 验收方案，覆盖空态、健康、异常、上传失败重试、认证失效等关键路径

## What's Changed

本次版本主要包含以下对外可见变化：

- 首页 KPI 结构改为更偏告警优先的运维视角
- 任务详情抽屉成为主要操作入口，降低任务表格的视觉与操作负担
- `retry-upload` 在上传失败场景下可直接从详情抽屉触发
- API 认证失效时不再依赖原生浏览器确认框，而是采用页内提示与设置流程
- 前端补齐 Playwright E2E 基础设施与 mock 场景，提升 UI 回归可验证性

## Upgrade Notes

`v0.1.1` 不引入 schema 变更，也不要求额外迁移步骤。

上线前建议确认：

- 如果你依赖嵌入式 `/ui/` 页面，请确认部署产物已更新到本版本的静态资源
- 如果你使用 API 认证，请验证 `401` 场景下设置对话框恢复流程符合你的运维预期
- 如果你依赖前端自动化回归，请在 CI 或本地环境中执行 Playwright E2E

## Validation

本次发布前已执行并通过以下门禁：

- `go test ./...`
- `go test -race ./internal/tasks ./internal/api ./internal/replication`
- `go vet ./...`
- `make e2e-quick`
- `cd frontend && npm run test:e2e`
- `cd frontend && npm run build`
- `make ui-build`

## Known Limits

- 当前认证提示流仍依赖前端全局事件与全局标记位，后续可继续做更稳健的状态收敛
- Playwright E2E 目前采用前端 route mock 作为最小验收方案，不等价于完整的端到端后端集成环境
