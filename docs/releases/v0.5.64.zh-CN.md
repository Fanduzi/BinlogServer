# Binlog Server v0.5.64 中文发布说明

> 对应版本：`v0.5.64`

发布日期：2026-10-13

v0.5.64 把新 Console 放到了 `/ui/`（#302）：用 React + shadcn/ui 重写的管理控制台。原来的 Vue 控制台在这一版里保留在 `/ui-classic/`，会在之后的版本里移除。`/ui/` 下的书签和深链接仍然可用。没有 API 变化。没有新配置项。没有 schema 迁移。schema 仍是 6。`minRequiredSchemaVersion` 仍是 6。地板仍是 v0.5.51。BinlogServerQA 对 main `56b221e65d7e047a154a00ae215b646cb8bd6031` 的 tip dogfood 通过，没有发现问题。

**历史改写。** BinlogServer 的提交历史在 2026-10-12 改写过（见 v0.5.60 说明）。此前的提交哈希都变了。请按 tag 或 PR 号查找改动。

## 亮点

- **`/ui/` 上的新 Console（PR #315、#317、#319、#320、#321、#327、#328、#329、#332；#302）。**
  - 任务和告警列表：服务端分页、过滤和 KPI。
  - `#/tasks/:id` 任务详情抽屉：状态、横幅、文件、事件、租约和运行记录、PITR 命令生成、启动/停止/删除。启动或停止后抽屉会自动刷新。
  - 新建、编辑、接管任务表单，以及带预览的批量创建。
  - 概览、数据源（支持按 host/port 查找）和 Worker 页面。
  - 界面里能用 `api_key` 模式：Console 读取 `GET /auth/config`，把凭证放在配置的请求头里发送。
  - 中英文。
- **`/ui-classic/` 上的经典 Vue 控制台，保留一个版本（PR #332）。** 行为和 v0.5.63 的 `/ui/` 相同。和 `/ui/` 一样不需要凭证就能加载，第一次 401 时再要求填写。两个控制台同源，浏览器存储用同一个键（`binlog_server_token`），在一边保存的 token 另一边也能用。
- **切换时附带的 Console 修复（PR #332）。** 没有 token 时打开深链接只弹出认证对话框；缺失的 worker 数显示 0；worker 角标统计已注册的 worker；批量预览补上 `totalRows` / `allPassed` / `hasFailed` 文案。

## 升级须知

- 替换二进制并重启即可。没有迁移，没有配置变化。
- `/ui/` 下的书签和深链接（例如 `/ui/#/tasks/12`）仍然可用，会打开新 Console。
- 依赖 Vue 界面的用户请改用 `/ui-classic/`，它会在之后的版本里移除。
- 按路径过滤的反向代理，除了 `/ui/` 和 `/auth/config`，还要放行 `/ui-classic/`。它们都不需要凭证。
- 已经是 schema 6 的库保持 schema 6。确认 `SELECT version, dirty FROM schema_migrations` 是 `(6, 0)`。`migrations/` 仍是 `000001` 到 `000006`，没有 `000007`。v0.5.64 在 schema 5 上不会启动：以退出码 1 结束，还没开始监听，提示含 `schema version too old` 和 `./migrate up`。还不是 schema 6 时，先按 [v0.5.56 升级](release-notes-v0.5.56.md)。地板仍是 v0.5.51。
- v0.5.63 的轮转期间 replay 修复、v0.5.62 的 401 规则和 `/auth/config`、v0.5.61 的 `limit` 规则、v0.5.60 的 `/replay` 规则、v0.5.59 的 legacy failback 规则和 v0.5.58 的 `storage_alert` 规则仍成立。从 v0.5.61 或更早版本升级，先读 [v0.5.62 说明](v0.5.62.zh-CN.md)：凭证错误返回 401，不再是 403。
