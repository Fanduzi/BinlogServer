# Binlog Server v0.5.23 中文发布说明

> 对应版本：`v0.5.23`

发布日期：2026-10-04

`v0.5.23` 在 `v0.5.22` 上核对封存上传和桶里的对象是不是同一串字节。封存分段上传之后，服务器对该对象做一次 HEAD，用 ETag 和这份封存文件比较。已发布的 v0.5.22 压缩包不做这次比较。它的 Console 文件表没有「校验」列。

## 核心变化

- 封存分段上传之后，服务器对该对象做一次 HEAD，把 ETag 和封存文件比较。不超过 16MiB 时，这个 ETag 是整文件 MD5。超过 16MiB 时，是和这次上传相同的 16MiB 分片 ETag，大约到 160GiB。没有周期性复查。正在写的 open 分段不做这次核对。
- 结果写在已有的 `binlog_files.checksum` 列，值为 `match` 或 `mismatch`。`GET /api/tasks/{id}/files` 返回这个值。Console 任务文件表的「校验」列显示它。`match` 表示这次 ETag 比较认定是同一串字节。`mismatch` 表示比较已经做完，字节不同。
- `mismatch` 保持 `UPLOADED`。它不算已校验，也不会停下复制。
- 上传失败保持 `UPLOAD_FAILED`，checksum 被清空。
- 对象 HEAD 失败时，checksum 留空，这一行仍是 `UPLOADED`。空值不是 `match`，也不是 `mismatch`。checksum 为空时，`GET /api/tasks/{id}/files` 不带这个字段。Console 这一格显示 `--`。读不了对象的上传器同样把 checksum 留空。空值不算已校验。「校验」是 `--` 时，既不是通过，也不是失败。正在写的 open 分段、被清空的 checksum、以及留空的 checksum，都是这同一个 `--`。

## 升级影响

- `v0.5.23` 不需要 schema migration。迁移仍只有 `000001_init_schema`。`binlog_files.checksum` 是原有列。
- 没有新的配置键。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
