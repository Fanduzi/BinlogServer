# Binlog Server v0.5.31 中文发布说明

> 对应版本：`v0.5.31`

发布日期：2026-10-05

`v0.5.31` 上，按时间点选回放窗口时，不再把 format description 和 previous-GTIDs 当成已复制的数据。这两条事件记录的是源 binlog 文件的创建时间。从源文件中部开始的备份会把这条 format description 写在第一个被复制的事件前面。`LATEST` 就是从当前文件中部开始。起点落在文件内部的 `FILE_POS` 也一样。到 `v0.5.30` 为止，`GET /api/tasks/{id}/replay` 带 `stop_datetime` 时会把这个创建时间算进覆盖范围，所以停止时间早于任何已复制事务时，仍会返回这个文件和一条命令。已发布的 v0.5.30 包仍然这样。

## 核心变化

- `GET /api/tasks/{id}/replay` 带 `stop_datetime`，以及同一个查询打在 `GET /api/tasks/{id}/replay/archive` 上，会跳过 format description 和 previous-GTIDs。计入窗口的是这两条头事件之后被复制的事件。事务自己的 GTID 事件仍然计入。跳过的只是 previous-GTIDs 这条文件头。
- UTC 停止时间早于第一个被复制的事件时，窗口是空的：HTTP 200，`paths` 是 `[]`，`command` 是空字符串。这个窗口的归档是空 tar。这不是 400。`stop_datetime` 晚于这第一个被复制的事件时，半开窗口盖住它，文件会被选中。窗口仍是 `[start, stop)`。停止时间不包含在内，与 `mysqlbinlog --stop-datetime` 相同。停止时间等于这第一个被复制事件的时间戳时，窗口仍是空的。
- 分段里只有 format description 和 previous-GTIDs、还没有被复制的事件时，任何停止时间都选不中它。
- 真实 rotate 之后从位置 4 打开的后续文件用同一条规则。文件开头的 format description 和 previous-GTIDs 不会把这个文件选进来。覆盖从它们之后的第一个被复制事件开始。
- 两个时间都不传时，仍是按 `limit` 的回放。`mysqlbinlog` 和 `mariadb-binlog` 的参数没有变化。命令仍以 `TZ=UTC` 开头，仍打印 `--stop-datetime`。Console 任务详情用的是同一个窗口。没有新的配置项。不需要 schema migration。

## 升级影响

- `v0.5.31` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 没有新的配置项。`cluster.failover_policy` 仍然不是开关。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
- 已经在磁盘上的分段不会被改写。这个版本只改变哪个 `stop_datetime` 会选中它们。
- 已发布的 v0.5.30 包上，停止时间落在源文件创建时间和第一个被复制事务之间时，仍可能返回这第一段。用过这种停止时间做恢复的，请核对：那个文件在所要的时间上并没有被复制的事务。
