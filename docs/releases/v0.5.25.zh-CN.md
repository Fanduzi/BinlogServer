# Binlog Server v0.5.25 中文发布说明

> 对应版本：`v0.5.25`

发布日期：2026-10-04

`v0.5.25` 在 `v0.5.24` 上，租约转到活着的 worker 之后，从死掉的 worker 留下的分段目录接着备份。已发布的 v0.5.24 包会把租约转走，不会从那个目录继续。

## 核心变化

- 租约可以走到活着的 worker。分段目录留在已经记下的 `binlog_files.file_path`，不跟着租约走。
- 这台 worker 能读到该目录：从里面最后一个完整事件接着写。同一个源文件不二次封存，也不另起 `{data_dir}/{task_id}/` 从位置 4 重拉。
- open 分段，或尚未 `UPLOADED` 的封存分段，在这台 worker 上读不到，而且 checkpoint 还不在已上传的封存对象里：任务 `FAILED`。`last_error` 以 `SEGMENT_NOT_ON_WORKER` 开头，并写出缺失路径。不会新建目录继续拉。把该路径挂过来或拷过来，再 `POST /api/tasks/{id}/start`。
- checkpoint 已经落在封存 `UPLOADED` 对象里：即使本地文件不在，也用现有上传客户端把对象读回来，从对象里最后一个完整事件继续。
- 同一台机器 `kill -9`、adopt、再 start 仍用本机目录。

## 升级影响

- `v0.5.25` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 没有新的配置项。`cluster.failover_policy` 仍然不是这条路径的开关。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
- checkpoint 已经在下一个文件的位置 4，且已封存的行都是 `UPLOADED`，仍从下一个文件的位置 4 开始。`v0.5.24` 的保留策略不变：先删对象，再删目录行，再删本地文件。`OBJECT_PURGE_FAILED` 留下本地文件。下次打开文件从下一个 binlog 文件继续。
