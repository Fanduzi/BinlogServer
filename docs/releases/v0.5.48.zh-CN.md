# Binlog Server v0.5.48 中文发布说明

> 对应版本：`v0.5.48`

发布日期：2026-10-07

GTID 启动，以及文件位点在任何事件之前撞上 MySQL 1236、再按已存 GTID 续传，不再封存或上传只有 magic 的占位文件，也不再留下空的 `task-<id>.binlog`。dump 的人工 Rotate（flags `0x20`，时间戳 0，没有 CRC）不写入封存段。runner 先等这条 Rotate 拿到真实源文件名，再打开分段文件。还只有 4 字节 magic 头的分段被删掉，不封存、不进目录、不上传。真实的文件位点 Rotate 仍写入被封存的分段。源库重启的 Rotate 仍按最后一个真实事件封上一个文件，然后在下一个文件上继续。这一版新封存的分段能通过 `mysqlbinlog --verify-binlog-checksum`。BinlogServerQA 的 tip dogfood 为 PASS。这一版不是 ADR 0005 的某一步。没有新的配置项。没有新的迁移。`minRequiredSchemaVersion` 仍是 3。

## 核心变化

- 启动模式为 `GTID` 的任务不再留下封存的 `task-<id>.binlog`。dump 的人工 Rotate 给出源文件名之前，runner 不打开分段。那个名字就是分段名。这条 Rotate 本身不写入。这一版启动后，`GET /api/tasks/{id}/files` 不列出 `task-<id>.binlog`，桶里也没有这个对象。
- 同一条 dump Rotate（flags `0x20`，时间戳 0，没有 CRC）不追加到封存段。这一版封存的分段，`mysqlbinlog --verify-binlog-checksum` 退出码为 0。已经复制的事件留在分段里。
- 文件位点续传在任何 dump 事件之前收到 MySQL 1236、再打开 GTID dump 时，为已清理的文件名打开的文件可能仍只有 4 字节 magic 头。这个文件被删除。不封存，不写入 `binlog_files`，不上传。随后 GTID dump 打开 Rotate 给出的源文件名。
- 不走这条路径的文件位点任务，仍把真实 Rotate 写入它封存的分段。源库重启仍会发一条指向下一个文件的人工 Rotate。这条事件不写入。上一个文件按最后一个真实事件封存，dump 在下一个文件上继续。规则和 v0.5.39（#214）一样。
- 旧二进制已经封存、尾部是这条无 CRC Rotate 的分段，包括已经在目录或桶里的 `task-<id>.binlog`，保持原样。`checksum` 和对象字节不变。

## 升级影响

没有新的迁移。`minRequiredSchemaVersion` 仍是 3。v0.5.48 在 schema 3 上可以启动。schema 4（`000004_pending_dump_cleanup`）仍是单进程可选、集群必须，规则和 v0.5.46、v0.5.47 一样。`migrations/` 仍是 `000001`、`000002`、`000003` 和 `000004`。下一个新迁移是 `000005`。

v0.5.48 在 schema 2 上不会启动，以退出码 1 结束，还没开始监听。提示含 `schema version too old` 和 `./migrate up`。

如果这套库还不是 schema 3，按 [v0.5.46 中文发布说明](v0.5.46.zh-CN.md)。schema 2 到 schema 3（`000003_task_desired_and_retry_budget`）在线。schema 1 到 schema 2 仍按 [v0.5.34 升级说明](v0.5.34.zh-CN.md)：停掉每一台进程，执行 `./migrate up`，然后只启动 v0.5.34 或更新的二进制。

没有新的配置项。没有元数据库的 standalone 不跑这些迁移。

v0.5.48 还在跑时不要 `./migrate down` 回到 schema 2。schema 4 上 `./migrate down --steps 1` 只丢掉 `pending_dump_cleanup`，回到 version 3。集群 worker 还依赖这一列时不要做这次 down。单进程可以留在 schema 3。

换上这一版二进制。之后的 GTID 启动和 1236 回退只封存源文件名。已经上传、带着无 CRC 人工 Rotate 的分段仍留在桶里。这一版不改写它们。升级后对新封存的分段执行 `mysqlbinlog --verify-binlog-checksum`，退出码为 0。BinlogServerQA 的 tip dogfood 在这个修复上为 PASS。

这一版不是 ADR 0005 的第 6、7、8、9 步。第 6 到第 9 步仍是后续工作。
