# Binlog Server v0.5.22 中文发布说明

> 对应版本：`v0.5.22`

发布日期：2026-10-04

`v0.5.22` 在 `v0.5.21` 上增加续传身份。已停止任务的 Console 详情同时显示配置的起点，以及下次 Start 继续的位点。已发布的 v0.5.21 压缩包只把起点显示成模式名。那里的 `GET /api/tasks/{id}/checkpoint` 返回存下来的 checkpoint 行，这个行可以和下次 Start 实际使用的位点不同。

## 核心变化

- 已停止任务的 Console 详情有两个身份。起点（Start）是配置的起点：`LATEST`，或 `FILE_POS` 写成 `file:pos`，或 `GTID` 写成 `gtid_set`。续传（Resume）是下次 Start 继续的位点，显示为 `file:pos`；这个续传带 GTID 时，显示为 `file:pos GTID gtid_set`。还没有续传时，这一行是「暂无，下次 Start 使用起点」。
- 已停止的 `LATEST` 任务起点仍显示 `LATEST`，不会被改写成 `FILE_POS`。续传行是本地最高 open 分段里最后一个完整事件的文件和位点。
- `GET /api/tasks/{id}/checkpoint` 返回下次 Start 使用的同一个续传：`file` 和 `pos`。只有存储的 checkpoint 就是这同一个文件和位点时，才包含 `gtid_set`。既没有 checkpoint 行，也没有完整的本地事件时，响应仍是 404 `checkpoint not found`。配置的起点留在任务的 `start` 对象里，不放进 checkpoint JSON。
- 停止请求和运行退出撞在一起时，任务不再停在 `STOPPING`。之后写入的一份更旧的 `STOPPING` 快照不会覆盖 `STOPPED`。

## 升级影响

- `v0.5.22` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 没有新的配置键。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
