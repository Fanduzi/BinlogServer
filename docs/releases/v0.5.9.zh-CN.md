# Binlog Server v0.5.9 中文发布说明

> 对应版本：`v0.5.9`

发布日期：2026-10-03

`v0.5.9` 是 `v0.5.8` 的运维补丁：文件目录为空时，files API 扫描磁盘上的分段；回放客户端必须和源库一致。

## 核心变化

- standalone 没配 `meta_dsn`，或 meta 里该任务没有 `binlog_files` 行时，`GET /api/tasks/{id}/files` 扫描 `{data_dir}/{task_id}/`，返回封存文件和 `.open.e<epoch>` 分段。`file_name` 是源文件名。`file_path` 是磁盘路径，open 分段带 `.open.e<epoch>`。顺序按源文件序号升序；同一序号先列封存名，再列 open epoch。`limit` 保留序号最大的那些。磁盘扫描没有位点，`start_pos` 和 `end_pos` 是 0。没有 checkpoint 行时，checkpoint 仍是 404 `checkpoint not found`。`binlog_files` 非空时行为不变（按 `sealed_at` 倒序），不会改成磁盘扫描。store 出错不会退回磁盘。Console 任务文件表显示磁盘文件名和 `file_path`。一次返回是 HTTP 200，带 `mysql-bin.000003` 和 `mysql-bin.000004.open.e1`，位点是 0，checkpoint 是 404。进程重启后该任务 id 是 404 `task not found`，目录还在。配了 meta 且目录有行时，位点来自目录（封存 `end_pos` 845，open `start_pos` 4 `end_pos` 488），磁盘上多出来的 `mysql-bin.000099` 不会被列出。
- 回放客户端必须和源库一致。MySQL 源用官方 MySQL `mysqlbinlog`。MariaDB 源用 `mariadb-binlog`。`mysqlbinlog --version` 印着 MariaDB（Debian `/usr/bin/mysqlbinlog` 经常就是 MariaDB，例如 11.8.6）时，退出码是 0，并注入文件里没有的 `SET @@session.check_constraint_checks=1`。MySQL 8.0 返回 `ERROR 1193`，一条数据都不进。文件没有坏。请用官方 `mysqlbinlog`（例如 `Ver 8.0.46`）。指南里已经写了这段。`v0.5.9` 的发布包带 `docs/guide`。
- Quick Start、落地页、部署文档和配置模板里的下载版本钉在 `v0.5.9`。

## 升级影响

- `v0.5.9` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 配置键没有变化。`PRODUCTION=true` 仍要求非空 `--encryption-key`。
- standalone 没配 `meta_dsn`，或该任务没有 `binlog_files` 行时，`GET /api/tasks/{id}/files` 列出封存文件和 `.open.e<epoch>` 分段。`file_name` 是源文件名，`file_path` 是磁盘路径。`start_pos` 和 `end_pos` 是 0。目录非空时仍按 `sealed_at` 倒序，不用磁盘扫描替换。store 出错不会退回磁盘。没有 checkpoint 行时仍是 404 `checkpoint not found`。standalone 进程重启后，该任务 id 是 404 `task not found`，目录还在。
- MySQL 源用官方 MySQL `mysqlbinlog` 回放。MariaDB 源用 `mariadb-binlog`。`mysqlbinlog --version` 印着 MariaDB 时退出码是 0，并注入 `SET @@session.check_constraint_checks=1`。MySQL 8.0 返回 `ERROR 1193`，一条数据都不进。文件没有坏。`v0.5.9` 的发布包带 `docs/guide`。
