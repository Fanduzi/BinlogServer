# Binlog Server v0.5.21 中文发布说明

> 对应版本：`v0.5.21`

发布日期：2026-10-04

`v0.5.21` 在 `v0.5.20` 上把回放窗口下载成一个 tar。DBA 可以一次取回 `GET /api/tasks/{id}/replay` 已经选出的分段，包括只是 `UPLOADED`、已经不在本进程上的封存分段，走同一条已认证 API 和 Console。已发布的 v0.5.20 压缩包没有回放集下载。单分段下载、文件列表和 JSON 回放命令没有变化。

## 核心变化

- `GET /api/tasks/{id}/replay/archive` 使用与 `GET /api/tasks/{id}/replay` 相同的 `limit` 和同一回放文件窗口。每个 tar 成员是该窗口的 basename，顺序与该窗口一致，不是主机路径。每个源序号仍是一个成员：同一序号既有封存名又有 `.open.e*` 时，成员是 epoch 最大的 open 分段，并保留 `.open.e*` 后缀。字节遵循现有单分段下载。本地文件优先，任务处于 `RUNNING` 或 `STOPPED` 时也包括 open 分段。本地没有的封存文件，只有目录行是 `UPLOADED` 且 `object_key` 非空时才从对象存储读取。`Content-Type` 是 `application/x-tar`。`Content-Disposition` 是 `attachment`，文件名是 `task-{id}-replay.tar`。
- 空窗口是 HTTP 200，正文是空的 ustar（1024 个零字节）。任务不存在是 404 `task not found`。每个选中分段都在写 tar 之前打开。有一个打不开或读不出来，响应是错误，不是半个归档。`LOCAL_ONLY`、`UPLOAD_FAILED`、空的 `object_key`、没有本地文件的 open 分段，以及本进程没有配置对象存储，仍是 404 `segment not found on this process`。
- Console 任务详情在现有复制回放动作旁边有「下载回放集」，使用与任务抽屉相同的 `limit=80`。`GET /api/tasks/{id}/files`、`GET /api/tasks/{id}/files/{name}` 和 `GET /api/tasks/{id}/replay` 没有变化。

## 升级影响

- `v0.5.21` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- `GET /api/tasks/{id}/replay/archive` 是新的只读 API。没有新的配置键。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
