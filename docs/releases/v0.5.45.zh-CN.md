# Binlog Server v0.5.45 中文发布说明

> 对应版本：`v0.5.45`

发布日期：2026-10-06

在 all-in-one 和集群上，`retry_attempt` 和 `consecutive_source_failures` 写在 `backup_tasks` 上，和任务行同一次写入。同一次 `SOURCE_UNREACHABLE` 连续失败里重启，计数和退避都接着走。两次重启，`SIGTERM` 和 `kill -9` 不论先后，仍在第 10 次连续失败进入 `FAILED`。`last_error` 以 `SOURCE_UNREACHABLE:` 开头，租约放开。`minRequiredSchemaVersion` 是 3。schema 2 上进程以退出码 1 结束。提示告诉操作员执行 `./migrate up`。这句话只打到 stderr，不写日志文件。这是 ADR 0005 的第 3 步，一共 9 步。没有新的配置项。跟踪为 #239，PR #244。QA 在 `ec1e4f1d` 上通过，覆盖 all-in-one 和 2 个 worker 的集群。

## 核心变化

- 有元数据库时，每一次 `SOURCE_UNREACHABLE` 失败都把 `retry_attempt` 和 `consecutive_source_failures` 写进 `backup_tasks`，和任务行同一次写入。dump 连上之后写成 0。操作员 Start 写成 0。认领不清零。
- 同一串失败里重启两次，`SIGTERM` 和 `kill -9` 不论先后，仍在第 10 次连续失败进入 `FAILED`。`GET /api/tasks/{id}` 的 `last_error` 以 `SOURCE_UNREACHABLE:` 开头，租约放开。连续失败次数最多 10 次。
- 重启之后会立刻再试一次源。这次失败之后的等待从已经落库的 `retry_attempt` 接着算（8 秒，然后 16 秒，然后 30 秒，以此类推）。不会从 1 秒重新起跳。等待上限仍是 30 秒。
- 同一个 worker 续租，或在自己的租约过期之后把它领回来，epoch 不变。另一个 worker 领走过期租约时，epoch 加 1。
- `FAILED` 把 `desired_run` 写成 `STOP`，把 `failed_spec_revision` 写成当时的 `spec_revision`。租约续期不再把这一行改成 `STOPPING`。
- 从只在事件里记连续失败的二进制升上来之后，第一次启动会在两列仍是 0 时，把那段连续失败抄进列一次。这一次的退避从 1 秒起跳。之后的重启用已经落库的 attempt。
- 没有元数据库的 standalone 计数只在进程内存里，进程退出就没了。这条路径不变。

## 升级影响

`minRequiredSchemaVersion` 是 3。v0.5.45 在 schema 2 上不会启动。如果这套库还不是 v0.5.44 已升好的 schema 3，在那些进程保持运行时执行 `./migrate up`。schema 2 到 schema 3（`000003_task_desired_and_retry_budget`）在线。这次迁移不需要重启。确认 `SELECT version, dirty FROM schema_migrations` 是 `(3, 0)`。然后再替换二进制。v0.5.45 在 schema 2 上启动会以退出码 1 结束，还没开始监听。提示里有 `schema version too old` 和 `./migrate up`。这句话只打到 stderr，不写日志文件。

schema 1 到 schema 2 是 v0.5.34 的迁移。这一步仍然要停掉连着这套元数据库的每一台 binlog-server。按 [v0.5.34 升级说明](v0.5.34.zh-CN.md)：停掉每一台进程，执行 `./migrate up`，然后只启动 v0.5.34 或更新的二进制。可以在线做的是从 schema 2 升到 schema 3。v0.5.45 在 schema 3 之前不会启动。

二进制回退到 v0.5.44 可以留在 schema 3 上。v0.5.45 还在跑的时候不要 `./migrate down` 回到 schema 2。v0.5.45 在 schema 2 上不会启动。

没有新的配置项。这一版不新增迁移。`migrations/` 仍是 `000001`、`000002` 和 `000003`。

## 已知行为

下面这些仍开着。#189、#193、#205、#224 在这一版之前就有。#239 在这一版修好。

- 故障切换后，同名封存段的 `end_pos` 写成 0。跟踪为 #189。
- 停止期间改密码再 Start 后，源库可能残留多余 Binlog Dump 连接。跟踪为 #193。
- GTID 启动或 1236 回退后写入无 CRC 的人工 Rotate，校验失败，并产生多余的 `task-N.binlog`。跟踪为 #205。
- 接管下载 `UPLOADED` 对象时进程崩溃，`.takeover-*` 临时文件会一直留在磁盘上。重启、重试成功后都不清理。跟踪为 #224。
