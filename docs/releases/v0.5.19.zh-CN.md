# Binlog Server v0.5.19 中文发布说明

> 对应版本：`v0.5.19`

发布日期：2026-10-04

`v0.5.19` 在 `v0.5.18` 上增加单分段下载。DBA 可以下载已经出现在 `GET /api/tasks/{id}/files` 里的一个 binlog 分段，走已认证的 API 和 Console，不必 SSH 到备份机。已发布的 v0.5.18 压缩包没有这个下载接口。

## 核心变化

- `GET /api/tasks/{id}/files/{name}` 流式返回该磁盘 basename 的原始字节（封存名或 `*.open.e*`）。`Content-Type` 是 `application/octet-stream`。`Content-Disposition` 使用这个 basename。正文长度是打开时的文件大小。
- 斜杠、反斜杠、`..` 或其他穿越形式返回 400 `invalid segment name`。任务不存在返回 404 `task not found`。basename 不在本进程该任务目录下，返回 404 `segment not found on this process`。本进程没有这个本地文件时，控制面不会按 catalog 路径或对象存储编造字节。任务处于 `RUNNING` 或 `STOPPED` 时，open 分段都可以下载。Console 文件表每一行有下载。
- `GET /api/tasks/{id}/files` 仍列出每一个文件名。`GET /api/tasks/{id}/replay` 和 Console 复制命令没有变化：每个源序号一条路径；同一序号既有封存名又有 `.open.e*` 时，路径是 epoch 最大的 open 分段，并保留 `.open.e*` 后缀。

## 升级影响

- `v0.5.19` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- `GET /api/tasks/{id}/files/{name}` 是新的只读 API。没有新的配置键。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
