# Binlog Server v0.5.28 中文发布说明

> 对应版本：`v0.5.28`

发布日期：2026-10-05

`v0.5.28` 在 `v0.5.27` 上，配了对象存储并且有目录（`meta_dsn`）时，按年龄做的保留不再删掉还没上传的过期封存 binlog 的唯一一份拷贝。已发布的 v0.5.27 包在本地文件早于 `storage.retention_days` 时仍会删掉这份本地文件。

## 核心变化

- 配了对象存储并且有目录（`meta_dsn`）时，按年龄做的保留不再删除 `upload_state` 为 `UPLOAD_FAILED` 或 `LOCAL_ONLY` 的过期封存 binlog。本地文件和目录行留下。复制继续跑。它不写 `last_error`，也不进入 `RETRY_BACKOFF`。是否过期仍看本地文件的修改时间，对照 `storage.retention_days`。
- `GET /api/tasks/{id}/events` 里，每个留下的文件有一条 `RETENTION_SKIPPED_NOT_UPLOADED`。消息写明文件名和它的 `upload_state`，例如 `mysql-bin.000003 upload_state=LOCAL_ONLY`。本进程还在跑时，再打开另一个 binlog 不会为同一个文件再追加这条事件。进程重启之后，下一次保留清理如果仍留下这个文件，会再追加一次这条事件。
- 跑保留清理的进程在 `GET /metrics` 上暴露 `binlog_server_retention_blocked_files{task_id}`：最近一次成功的清理仍留下的这类过期文件数。后面某次清理把它们删掉后，这个数下降。重启之后，在下一次保留清理之前，它保持 0。保留清理仍在复制循环打开 binlog 文件时执行。只跑控制面的进程不做保留清理，所以那边的这个 gauge 保持 0。这条事件仍在 `GET /api/tasks/{id}/events`。
- 这一行变成 `UPLOADED` 之后，下一次保留清理先删对象，再删目录行，再删本地文件。已封存的 `UPLOAD_FAILED` 仍由后台补传捡起，也由已有的手动补传 `POST /api/tasks/{id}/files/retry-upload` 捡起。两条路都可以把这一行变成 `UPLOADED`。已经是 `UPLOADED` 的行、`OBJECT_PURGE_FAILED`，以及没配置上传时的本地保留，都保持原样。
- `LOCAL_ONLY` 不会被后台补传捡起。手动补传也只选择已封存的 `UPLOAD_FAILED`，所以它也不会上传 `LOCAL_ONLY`。封存时从没配过对象存储的文件，过了保留期仍留在磁盘上，gauge 继续计着它。之后再配上对象存储，也不会上传这一行。
- 没配 `meta_dsn` 的单机仍按年龄删除本地封存文件，包括从没进过桶的那一份。桶可能中断的时间长于 `storage.retention_days` 时，不要把这种模式当成唯一副本。

## 升级影响

- `v0.5.28` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 没有新的配置项。`cluster.failover_policy` 仍然不是开关。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
