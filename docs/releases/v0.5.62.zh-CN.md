# Binlog Server v0.5.62 中文发布说明

> 对应版本：`v0.5.62`

发布日期：2026-10-13

v0.5.62 改变了鉴权失败的返回码，这是一个**兼容性变化**：凭证缺失、格式错误或不正确，现在一律返回 HTTP 401，不再返回 403（PR #316）。bearer 模式的 401 还带 `WWW-Authenticate: Bearer realm="binlog-server"`。这一版还新增了不需要认证的 `GET /auth/config`，让内置的 Vue 控制台能在 `api_key` 模式下使用，`Bearer` 前缀不再区分大小写，任务不存在时显示服务端的错误文字（PR #318）。新的 React 控制台正在 `console/` 里开发（PR #315、#317、#319），**还没有嵌入**：`/ui/` 仍是 Vue 控制台。没有新配置项。没有 schema 迁移。schema 仍是 6。`minRequiredSchemaVersion` 仍是 6。地板仍是 v0.5.51。BinlogServerQA 对 main `ef6fc2ee7447f4dea4195fdd8a9fad4a6db4cfc8`（evidence-tip-ef6f）的 tip dogfood 通过，没有 P0、P1。一个不是回归的 P2（v0.5.61 上也有）列在「已知行为」里。

**历史改写。** BinlogServer 的提交历史在 2026-10-12 改写过（见 v0.5.60 说明）。此前的提交哈希都变了。请按 tag 或 PR 号查找改动。

## 兼容性变化：401 取代 403

| 请求 | v0.5.61 | v0.5.62 |
|---|---|---|
| 没带凭证 | 401 | 401 |
| bearer 模式，头里没有 `Bearer ` 前缀（例如只有 token、`Basic …`） | 403 | **401** |
| bearer 模式，token 错误 | 403 | **401** |
| api_key 模式，key 错误 | 403 | **401** |
| 凭证正确 | 200 | 200 |

- 服务端只有一份共享凭证，没有按用户的权限，所以校验失败只意味着「未认证」。403 留给以后有了用户和角色之后的「已认证但无权限」。
- bearer 模式的每个 401 都带 `WWW-Authenticate: Bearer realm="binlog-server"`。浏览器不会因为 Bearer 质询弹出登录框。
- 两个控制台收到 401 都会重新打开设置，token 过期或填错时，运维能直接回到 token 输入框，而不是看到一屏失败的请求。

**升级前检查：** 把 403 当作「token 错误」的监控探针、脚本或代理（例如对 `/api/*` 或 `/metrics` 按 `status == 403` 告警），要改成看 401。

## 核心变化

- **`GET /auth/config`，不需要凭证（PR #318）。** 返回 `{"enabled", "mode", "header", "scheme"}`，例如 `{"enabled":true,"mode":"bearer","header":"Authorization","scheme":"Bearer"}` 或 `{"enabled":true,"mode":"api_key","header":"X-BS-Key"}`。不会返回 token 或 key。响应带 `Cache-Control: no-store`。如果服务前面的代理只放行 `/api/*` 和 `/ui/`，也要放行 `/auth/config`。
- **Vue 控制台支持 `api_key` 模式（PR #318）。** 控制台先读一次 `/auth/config`，再把保存的值放进配置的请求头（`Authorization: Bearer …` 或你的 `api_key_header`）。以前它总是发 `Authorization: Bearer`，`api_key` 模式下每个请求都失败。连到没有 `/auth/config` 的旧版服务时，回退到 Bearer。
- **Bearer 前缀不区分大小写（PR #318）。** `Bearer`、`bearer`、`BEARER` 都可以，token 前可以有一个或多个空格或制表符（RFC 7235 / RFC 6750）。只有前缀没有 token 仍是 401。
- **任务不存在时显示服务端消息（PR #318）。** 任务详情抽屉显示服务端的错误文字，例如 `task not found`，而不是笼统的失败提示。
- **`console/` 里的新控制台，尚未嵌入（PR #315、#317、#319，#302 的一部分）。** 用 React + shadcn/ui 重写，已有外壳、任务/告警列表、`#/tasks/:id` 的任务详情抽屉和创建/编辑/接管对话框。它在仓库里构建和测试，但**没有在 `/ui/` 提供**。在之后的切换版本之前，你用到的东西都不变。
- **文档。** 排障表和配置指南写明了 401 行为和 `/auth/config`。

## 升级影响

- 把所有预期「凭证错误返回 403」的地方改成 401（见上表）。
- 如果反向代理按路径过滤，放行 `GET /auth/config`，控制台靠它决定用哪个请求头。它不需要凭证，也不返回凭证。
- `/healthz` 仍然开放。`/ui/` 不带凭证也能打开，第一次收到 401 时要求填写。

没有新迁移。已经在 schema 6 上的库仍是 schema 6。确认 `SELECT version, dirty FROM schema_migrations` 是 `(6, 0)`。`migrations/` 仍是 `000001` 到 `000006`，没有 `000007`。`minRequiredSchemaVersion` 仍是 6：v0.5.62 在 schema 5 上不会启动，以退出码 1 结束，还没开始监听，提示含 `schema version too old` 和 `./migrate up`。还不是 schema 6 时先按 [v0.5.56 升级](v0.5.56.zh-CN.md)。地板仍是 v0.5.51。没有新配置项。v0.5.61 的 `limit` 规则、v0.5.60 的 `/replay` 规则、v0.5.59 的旧版回切规则和 v0.5.58 的 `storage_alert` 规则仍成立。
