# Binlog Server v0.5.7 中文发布说明

> 对应版本：`v0.5.7`

发布日期：2026-10-02

`v0.5.7` 是 `v0.5.6` 的运维补丁：meta 故障期间的任务读取、MariaDB flavor 提示、单机 Worker 计数，以及嵌入 Console 的 Flavor 控件。

## 核心变化

- 控制面任务读取会重试 meta MySQL 的瞬时错误。`GetTask`、任务列表、列表计数和 `LoadCheckpoint` 走与租约写入相同的重试策略。连接池按 `ConnMaxLifetime` 30s 回收，短暂的 orchestrator 切换不会把进程留在已降级的 writer 上。任务不存在仍是 not-found，不会重试。
- `flavor=mysql` 读不到 `@@server_uuid`（空结果或未知系统变量）时仍是 `SOURCE_IDENTITY_UNAVAILABLE`，并告诉运维这看起来像 MariaDB，应设置 `flavor=mariadb`。`flavor=mariadb` 的身份识别没有改。Quick Start 和落地页对 MariaDB 源写 `"flavor":"mariadb"`。Console 的 Flavor 控件是 mysql / mariadb 二选一。
- 单机和其他单进程部署以 `worker_id=standalone` 持有任务，且不写心跳。概览不再把这个 owner 计成离线 Worker：`worker_count=0`，`single_process=true`，`GET /api/workers` 为空。Console 文案是「单机，任务由本进程拉取」。若存在 `standalone` 心跳，该行仍是 Worker。
- 嵌入 Console 的创建任务和批量创建 Flavor 下拉重新能渲染。提示文案不再包含 vue-i18n@9 在编译生产文案时会拒绝的原始 `@@server_uuid`。语言包在 UI 构建前和 CI 里都会编译检查。
- 落地页控制台截图是真实 PNG（`console-dashboard.png`、`task-detail.png`、`swagger.png`）。`scripts/check-landing-assets.sh` 在 CI 和 release 工作流里都会跑。
- 落地页和生产模板写了 Day-1 安装与第一次备份路径。Quick Start、落地页、部署文档和配置模板里的下载版本钉在 `v0.5.7`。

## 升级影响

- `v0.5.7` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 短暂 meta MySQL 中断时，以前直接 500 的任务读取现在在存储层重试。找不到任务仍然是找不到。
- MariaDB 源必须提交 `"flavor":"mariadb"`。保持 `mysql` 仍会在启动时以 `SOURCE_IDENTITY_UNAVAILABLE` 失败；错误信息现在点名 MariaDB 和 `flavor=mariadb`。
- 单机概览 JSON 增加 `single_process`。本进程自己拉流且没有 Worker 心跳时，`worker_count` 为 `0`，`workers` 为空。有心跳的集群 Worker 不变。
- 配置键没有变化。`PRODUCTION=true` 仍要求非空 `--encryption-key`。
