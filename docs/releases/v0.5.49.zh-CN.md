# Binlog Server v0.5.49 中文发布说明

> 对应版本：`v0.5.49`

发布日期：2026-10-07

故障切换之后，目录里已经有过的源文件，再封存同名分段时，`start_pos` 和 `end_pos` 按文件里的事件来写。`start_pos` 是第一个事件的位置。`end_pos` 是最后一个事件的结束位点。这两个数是时间点恢复要用的区间。换上这一版之前，这一行可能是 `end_pos` 为 0，或者 `start_pos` 和 `end_pos` 都等于续传位点，而文件里的事件其实从位点 4 一直到最后一个事件。epoch 1、同名的第三个 epoch，以及文件位点续传撞上 MySQL 1236 再按已存 GTID 继续之后封存的分段，都按这个规则。同一文件、位点为 0 的人工 Rotate 不再把正在复制的位点清成 0。已经是 `UPLOADED` 的行保持原样。BinlogServerQA 的 tip dogfood 在 `e690c438` 上为 PASS。这次没有新的问题。这一版不是 ADR 0005 的某一步。没有新的配置项。没有新的迁移。`minRequiredSchemaVersion` 仍是 3。

## 核心变化

- 新租约再封存同名分段时，包括 epoch 1 和同名的第三个 epoch，`start_pos` 等于第一个事件的位置，`end_pos` 等于最后一个事件的结束位点。这两个数和封存文件里的事件区间一致，也和 `mysqlbinlog` 读到的区间一致。这一行不是 `end_pos` 为 0，也不是 `start_pos` 和 `end_pos` 都等于续传位点。`GET /api/tasks/{id}/files` 和 Console 文件表显示这两个数。
- 文件位点续传在任何 dump 事件之前收到 MySQL 1236、再按已存 GTID 继续时，封存的源文件同样按这个规则写位点。封存行对得上文件里的第一个和最后一个事件。
- 同一文件、位点为 0 的人工 Rotate 不把正在复制的位点写成 0。下一次 Rotate 不会把已经复制的事件封成 `end_pos` 0。
- 已经是 `UPLOADED` 的行保持原样。旧二进制写成 `end_pos` 0，或两个位点都等于续传位点的行，仍是原来的数。下载和回放不变。
- 这一版封存的分段仍不会留下 `task-<id>.binlog`。`mysqlbinlog --verify-binlog-checksum` 退出码仍是 0。这是 v0.5.48（#205）的规则。这一版没有改它。

## 升级影响

没有新的迁移。`minRequiredSchemaVersion` 仍是 3。v0.5.49 在 schema 3 上可以启动。schema 4（`000004_pending_dump_cleanup`）仍是单进程可选、集群必须，规则和 v0.5.46、v0.5.47、v0.5.48 一样。`migrations/` 仍是 `000001`、`000002`、`000003` 和 `000004`。下一个新迁移是 `000005`。

v0.5.49 在 schema 2 上不会启动，以退出码 1 结束，还没开始监听。提示含 `schema version too old` 和 `./migrate up`。

如果这套库还不是 schema 3，按 [v0.5.46 中文发布说明](v0.5.46.zh-CN.md)。schema 2 到 schema 3（`000003_task_desired_and_retry_budget`）在线。schema 1 到 schema 2 仍按 [v0.5.34 升级说明](v0.5.34.zh-CN.md)：停掉每一台进程，执行 `./migrate up`，然后只启动 v0.5.34 或更新的二进制。

没有新的配置项。没有元数据库的 standalone 不跑这些迁移。

v0.5.49 还在跑时不要 `./migrate down` 回到 schema 2。schema 4 上 `./migrate down --steps 1` 只丢掉 `pending_dump_cleanup`，回到 version 3。集群 worker 还依赖这一列时不要做这次 down。单进程可以留在 schema 3。

换上这一版二进制。之后封存的分段，`start_pos` 和 `end_pos` 按文件里的第一个和最后一个事件来写。已经是 `UPLOADED` 的行保持原样，包括旧二进制写成 `end_pos` 0 的行。这一版不改写它们。BinlogServerQA 的 tip dogfood 在 `e690c438` 上为 PASS。这次没有新的问题。

这一版不是 ADR 0005 的第 6、7、8、9 步。第 6 到第 9 步仍是后续工作。
