# Binlog Server v0.5.24 中文发布说明

> 对应版本：`v0.5.24`

发布日期：2026-10-04

`v0.5.24` 在 `v0.5.23` 上，本地保留删掉过期封存分段时，把桶里的对象一起删掉。已发布的 v0.5.23 压缩包只删本地文件，对象留在桶里。对象删除失败时任务会重试。后来删除成功，复制从下一个 binlog 文件继续。

## 核心变化

- 复制循环打开文件时，早于 `storage.retention_days` 的封存分段，若该行是 `UPLOADED` 且有对象键，先从桶里删除，再删目录行，再删本地文件。是否过期看本地文件的修改时间，不看 `sealed_at`。还在保留期内的分段留下。open 分段不删，保留也不会为它删对象。
- 没有配置上传时，本地保留不变。
- 对象删除失败时，本地文件留下。`checksum` 保持原样：`match`、`mismatch`，或空。空值不是 `match`，也不是 `mismatch`。这一行仍是 `UPLOADED`。任务重试，`last_error` 以 `OBJECT_PURGE_FAILED` 开头。对象已经不在（HTTP 204 或 404）算成功，这次重试可以做完。
- 分段封存之后，checkpoint 先记到下一个文件，然后才做保留清理。如果接着打开下一个文件失败，重试从下一个文件继续。它不会再封存刚刚封过的那个文件，所以不会停在 `sealed file already exists`。

## 升级影响

- `v0.5.24` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- 没有新的配置键。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
- 已经停在 `sealed file already exists`、并且 checkpoint 仍停在那个已封存文件上的任务，这个版本不会把它修好。把那个已封存文件挪开一次，下次重试才能继续。
