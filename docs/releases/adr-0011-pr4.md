# ADR 0011 PR-4: wire the transition model

This note is the operator contract for migration `000011`. It is not a published version bump. The historical PR-2 note still describes the build that did not install the procedure. This build does.

## Order

Stop every old node first. Then `migrate up`. Then start the new nodes. A new binary refuses to start when `schema_migrations` is below 11 and tells the operator to run `./migrate up`.

`000011` checks `information_schema` and skips a column or table that is already there, so a failed up can be run again. MySQL 8 has no `ADD COLUMN IF NOT EXISTS`. The precheck aborts when a worker registration is still live, when `information_schema.innodb_trx` has a transaction older than 5 seconds, or when `log_bin` is on and the account has neither `SUPER` nor `log_bin_trust_function_creators`. Five seconds is the longest idle cap this build publishes. A process may arm a shorter `idle_kill`. SQL cannot see that setting.

The `BEFORE UPDATE` trigger and `binlog_server_kill_trx` are not inside the golang-migrate up file. golang-migrate sends that file as one statement, and a compound `BEGIN`/`END` body does not belong there. `cmd/migrate` installs `migrations/000011_cluster_ownership.guards.sql` after the up commits, one statement at a time, split on a line that is exactly `-- next`. An object that is already in `information_schema` is skipped.

## row_generation

`backup_tasks_bu_generation` rejects an `UPDATE` that does not set `row_generation` to the old value plus one. The signal text is `backup_tasks update must bump row_generation`. The product's own upsert, pending-dump save, and legacy desired reconcile already bump it. A hand-written `UPDATE`, including the SQL in `scripts/e2e/smoke-epoch-segments.sh`, has to do the same.

The up also rewrites stored `FAILED` rows whose `desired_run` is `STOP` to `RUN`, and sets `failed_reason` to `LEGACY_UNKNOWN`. An operator who still wanted that task stopped has to Stop it again after the migration. Do not change `LEGACY_UNKNOWN` back to `STOP`.

## Procedure privileges

`binlog_server_kill_trx` is `SQL SECURITY DEFINER`. The definer is `CURRENT_USER` at install time: the account that runs `migrate up`. Do not drop that account. A later `UPDATE` of `backup_tasks` and a `CALL` both fail closed without it.

That account needs `PROCESS` so the procedure can see another account's row in `information_schema.innodb_trx`. It also needs `CONNECTION_ADMIN` or `SUPER` so the `KILL` inside the procedure is allowed.

`GRANT EXECUTE ON PROCEDURE binlog_server_kill_trx` only to the binlog-server account. Do not grant it by giving other accounts `GRANT ALL` on the database.

MySQL 8 reads `performance_schema.data_locks`. Without that view the procedure fails closed. MariaDB has no `data_locks`. Its InnoDB lock view shows only locks that are already part of a wait, so a canary with no waiter does not see the lock and `cluster.side_kill=auto` does not turn on. `auto` is supported on MySQL. The procedure names `mysql.rds_kill` for RDS MySQL, RDS MariaDB, and Aurora MySQL. The gap between the lock check and the `KILL` is a few microseconds inside the server. The worst case is a thread that has already answered Sleep twice. That is accepted.

`side_kill` stays off when the procedure was not created.

## Protocol fence

New nodes write `worker_registrations.cluster_protocol_version` 11. After the migration, a live registration still below 11 makes a new node refuse claims and open critical `MIXED_VERSION` on `_cluster`. That is the signal that an old node is still in the cluster. The claim query does not join `worker_registrations`.

`cluster.storage` is registered once in `cluster_storage`. A later node with a different mode does not claim.

## Down

Down drops `binlog_server_kill_trx` first, then the trigger. It refuses to continue while a registration at protocol 11 or newer is still live, or while a `pending_delete` lease is still live. It then drops the new columns and tables. It does not write `LEGACY_UNKNOWN` rows back to desired `STOP`.

Stop the new nodes before `migrate down`. An older binary does not know schema 11.

## What stays desired RUN

A runner error that is not `SOURCE_ACCESS_DENIED` or `SOURCE_LOG_BIN_OFF` yields `LEASE_DEGRADED` and keeps desired `RUN`. Those two allowlist errors retry for at least two minutes, then `FAILED`, and desired stays `RUN`. ADR 0005's failure-policy section points here. The historical step text in 0005 is unchanged.
