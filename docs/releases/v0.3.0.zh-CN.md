# Binlog Server v0.3.0 中文发布说明

> 对应版本：`v0.3.0`

`v0.3.0` 在限流层完成两项关键加固：新增面向对象存储上传的令牌桶限速器，并修复 IP 限流器 LRU 淘汰顺序错误的 Bug；同时对 e2e CI 矩阵进行分层改造，引入 meta-failover 场景的自动验证。

## 核心变化

- 新增 `UploadRateLimiter`（令牌桶，`internal/upload`）：防止 binlog 文件突发上传打爆对象存储带宽或 API 限额。`NewUploadRateLimiter(uploadsPerSecond, burst)` 支持传入 `<=0` 表示不限速；`Wait(ctx)` 在令牌可用前阻塞，ctx 取消时立即返回。8 个单元测试，`-race` 验证无数据竞争。
- 修复 `IPRateLimiter` LRU 淘汰 Bug：`lastSeen` 此前仅在慢路径（创建条目时）更新，导致 LRU 淘汰的是最早创建而非最久未访问的 IP。改用 `atomic.Int64` 在读路径和写路径均原子更新，彻底修复淘汰语义。
- 重构 e2e CI 矩阵为三层策略：PR 只跑 `quick + retry-upload`；push 到 `main` 额外追加 `meta-failover`；手动 dispatch 可选任意 profile。`cluster-roles`、`observability`、`worker-crash-recovery` 三个 job 改为仅限 dispatch 触发。

## 升级影响

- `v0.3.0` 无 schema 变更，不需要额外迁移步骤。
- 后端 API 契约无破坏性修改。
- `UploadRateLimiter` 尚未接入上传流水线，本次升级无需变更任何配置。

## 运维收益

- LRU 修复后，IP 限流器在高 IP 多样性流量下淘汰策略更公平，不再误淘汰高频访问的合法 IP。
- 上传限速基础设施已就位，后续流水线集成无需改动限速核心逻辑。
- `main` 分支每次推送自动触发 meta-failover e2e 验证，集群层面故障可更早暴露。
