# Binlog Server v0.1.0 中文发布说明

> 对应版本：`v0.1.0`
> 文档定位：仓库内中文版 release note，可作为 GitHub Release 的中文补充阅读材料

Binlog Server `v0.1.0` 是项目的首个公开版本。它提供面向 MySQL binlog 拉取场景的 API 驱动控制面：持续拉取 binlog、可靠落盘本地文件、持久化 checkpoint，并支持可恢复的任务执行、可选的 metadata 协调、S3-compatible upload、Prometheus metrics 与基础 OpenTelemetry tracing。

## Highlights

- Binlog Server 首次以可用的公开版本发布，具备 MySQL binlog 拉取与任务编排能力
- 任务起点模式在 `LATEST`、`FILE_POS`、`GTID` 三种路径上具备一致语义
- checkpoint 采用更明确的持久化语义：只有本地 `fsync` 成功后才推进
- 提供可选的 metadata 协调、lease 管理、S3-compatible upload、Prometheus metrics 与基础 OpenTelemetry tracing
- 仓库补齐了开源使用所需的基础治理：安全策略、changelog 维护约定、release checklist、issue 入口治理与入口层文档

## What's Included

这个版本包含以下对外可见能力：

- 用于创建、列出、启动、停止任务的 HTTP API
- Web UI 与 Swagger 入口
- 支持任务恢复执行的 MySQL replication 运行时
- checkpoint 持久化与接管恢复行为
- 用于协调与 cluster lease 模式的 metadata 存储支持
- 对 sealed binlog 文件的可选 S3-compatible upload
- Prometheus-compatible metrics 端点
- 可选的 OpenTelemetry tracing 基础能力
- 仓库工作流中覆盖 smoke、compression、observability、cluster-role 等路径的 E2E 验证基础

## Upgrade Notes

这是项目的首个公开版本，因此不存在上一条公开版本线可供升级。

在环境中采用 `v0.1.0` 之前，请至少确认以下事项：

- 如果使用 `meta_dsn`，请在启动服务前先执行数据库迁移
- 生产环境不要保持 API auth 关闭；请检查 `SECURITY.md` 与 `docs/security.md`
- 如果启用 S3-compatible upload，需要提供完整的 upload 配置
- 如果依赖 dashboard 或告警，请在上线前确认当前 metrics 与 tracing 行为符合预期
- 贡献者若修改 SQL/schema 路径，应遵循现有 `sqlc` 工作流与验证门禁

## Known Limits

- 这是 `v0.1.0`，不是已经承诺长期小版本向后兼容的稳定产品线
- 项目定位是 binlog 拉取 / 备份控制服务，而不是完整 CDC 平台
- tracing 目前保持基础能力，且默认关闭
- upload 支持以 S3-compatible API 为目标，生产使用前应先结合你的对象存储做验证
- schema、config、observability 相关变化仍应被视为显式 release review 项，而不是默认“替换二进制即可升级”
