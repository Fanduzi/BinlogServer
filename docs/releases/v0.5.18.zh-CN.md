# Binlog Server v0.5.18 中文发布说明

> 对应版本：`v0.5.18`

发布日期：2026-10-04

`v0.5.18` 在 `v0.5.17` 上增加回放集。`GET /api/tasks/{id}/replay` 在与 `GET /api/tasks/{id}/files` 相同的目录窗口里，每个源文件序号返回一条磁盘路径。已发布的 v0.5.17 压缩包没有这个回放接口。

## 核心变化

- `GET /api/tasks/{id}/replay` 在与 `GET /api/tasks/{id}/files` 相同的目录窗口里，每个源文件序号返回一条磁盘路径。路径按序号升序。同一序号既有封存名，又有一个或多个 `.open.e*` 时，路径是 epoch 最大的 open 分段，并保留 `.open.e*` 后缀。较小的 `limit` 保留序号最大的那些，不是 `sealed_at` 最新的那些。
- `source.flavor` 为 `mysql` 时，`client` 是 `mysqlbinlog`，`client_hint` 是 `MySQL mysqlbinlog`。为 `mariadb` 时，两者都是 `mariadb-binlog`。flavor 为空时，client 为空。空目录返回 `paths: []`。
- files API 没有变化，仍列出每一个文件名。Console 任务详情显示这条命令，并可以复制。停止、恢复、认领，以及 kill-9 后续传都没有变化。

## 升级影响

- `v0.5.18` 不需要 schema migration。迁移仍只有 `000001_init_schema`。
- `GET /api/tasks/{id}/replay` 是新的只读 API。没有新的配置键。`PRODUCTION=true` 仍要求非空 `--encryption-key`。30 秒阈值没有变化。
