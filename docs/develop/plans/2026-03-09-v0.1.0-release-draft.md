# Binlog Server v0.1.0

Binlog Server is a service for pulling MySQL binlog into durable local files, persisting checkpoint state, and managing replication tasks through an API-driven control plane.

## Highlights

- First public release of Binlog Server as a usable MySQL binlog pull and task orchestration service
- Stable task start modes across `LATEST`, `FILE_POS`, and `GTID`
- Durable checkpoint semantics: checkpoint only advances after local `fsync` succeeds
- Optional metadata-backed coordination, lease management, S3-compatible upload, Prometheus metrics, and basic OpenTelemetry tracing
- Repository baseline improved for open source use with security policy, changelog discipline, release checklist, issue governance, and entry-layer documentation

## What's Included

This release includes the following user-visible capabilities:

- HTTP API for creating, listing, starting, and stopping tasks
- Web UI and Swagger entry points
- MySQL replication runtime with resumable task execution
- Checkpoint persistence and takeover-aware recovery behavior
- Metadata storage support for coordination and lease-backed cluster mode
- Optional S3-compatible upload for sealed binlog files
- Prometheus-compatible metrics endpoint
- Optional OpenTelemetry tracing foundation
- E2E coverage for smoke, compression, observability, cluster-role, and related hardening paths in the repository workflow

## Upgrade Notes

This is the first public version, so there is no previous public release line to upgrade from.

Before adopting `v0.1.0` in an environment, review these points:

- If you use `meta_dsn`, run database migrations before starting the service
- Production deployments should not keep API auth disabled; review `SECURITY.md` and `docs/security.md`
- If you use S3-compatible upload, provide a complete upload configuration set
- If you rely on dashboards or alerts, validate current metrics and tracing behavior before rollout
- Contributors touching SQL/schema paths should follow the existing `sqlc` workflow and verification gate

## Known Limits

- This is a `v0.1.0` release, not a long-lived stable series with backward-compatibility guarantees across many minor versions
- The project is positioned as a binlog pull / backup control service, not a full CDC platform
- Tracing is intentionally basic and default-off
- Upload support targets S3-compatible APIs and should be validated against your object storage before production rollout
- Operators should treat schema, config, and observability changes as explicit release review items rather than assuming zero-touch upgrades
