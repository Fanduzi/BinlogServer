# 学习章节实战检查清单

> 这不是考试评分表，而是项目学习的“防走偏清单”。
> 目标是：每学完一章，都能留下可复盘的工程证据。

## 1. 怎么用（轻量版）

1. 每章结束后，用 5~10 分钟做一次检查。
2. 不追求“满分”，只关注“是否真的学会并能复现”。
3. 如果某项做不到，先记录卡点，再回看该章，不需要硬闯下一章。

## 2. 每章通用三件事

1. **讲得清**：能用自己的话讲清本章核心概念。
2. **做得出**：至少完成 1 个最小动手动作。
3. **留得住**：留下命令和关键输出，未来可复查。

## 3. 分章检查（00-12）

### 第 0 节（项目总览）

- 看懂标准：能说清控制面、数据面、可观测面分别负责什么。
- 动手动作：指出三条主链路对应的入口文件。
- 留痕建议：写一份 10 行以内的系统摘要。

### 第 1 节（启动与装配）

- 看懂标准：能复述 `main -> app.Run -> server` 主链路。
- 动手动作：启动服务并验证 `/healthz`。
- 留痕建议：记录一次 role 不同导致行为差异的观察。

### 第 2 节（任务模型与调度）

- 看懂标准：能解释关键状态流转与停止语义。
- 动手动作：创建任务、启动/停止并查看 `events`。
- 留痕建议：记录一次“状态变化 + 事件”对照截图或输出。

### 第 3 节（MySQL 复制 runner）

- 看懂标准：能讲清 `rotate -> seal -> metadata -> upload`。
- 动手动作：观察 checkpoint 与 files 的变化。
- 留痕建议：记录“为什么 checkpoint 不能提前推进”的解释。

### 第 4 节（元数据持久化）

- 看懂标准：能说清 tasks/checkpoints/events/files 各表职责。
- 动手动作：重启后验证任务与位点恢复。
- 留痕建议：记录“任务恢复”和“位点恢复”的两段式区别。

### 第 5 节（Gin API 层）

- 看懂标准：能说明 handler 与 scheduler/store 的边界。
- 动手动作：至少调用 2 条 API 并验证状态码。
- 留痕建议：写一条 4xx 与 5xx 划分的经验总结。

### 第 6 节（Vue 前端）

- 看懂标准：能说明 `api.js` 与 `App.vue` 的职责分层。
- 动手动作：前端构建成功并验证关键页面可打开。
- 留痕建议：记录一次“容错加载”对体验的影响。

### 第 7 节（测试与安全）

- 看懂标准：理解“证据先于结论”。
- 动手动作：做一条最小“先失败后修复”闭环。
- 留痕建议：记录命令、输出和修复前后差异。

### 第 8 节（orchestrator 探测）

- 看懂标准：说清“发现候选”与“纳入拓扑”的差异。
- 动手动作：整理 2 条你环境里的风险控制策略。
- 留痕建议：给出可追溯的结论来源（文档/代码位置）。

### 第 9 节（cluster 角色装配）

- 看懂标准：能区分 control-plane / worker / all-in-one。
- 动手动作：验证 worker 探针与 API 暴露边界。
- 留痕建议：记录一次 role 配错时的现象与定位方式。

### 第 10 节（lease/claim/heartbeat）

- 看懂标准：理解 claim、续租、fail-safe 的关系。
- 动手动作：观察 worker online/offline 变化。
- 留痕建议：写一句你对 epoch/fencing 的理解。

### 第 11 节（cluster API 与前端观测）

- 看懂标准：知道 workers/runs 两类接口各自解决什么问题。
- 动手动作：验证 runs 的 limit 与排序语义。
- 留痕建议：记录“online 不等于 running”的一个实例。

### 第 12 节（e2e 与发版）

- 看懂标准：理解为什么 e2e 证据是发布门槛。
- 动手动作：执行至少 1 条 cluster e2e 场景。
- 留痕建议：产出一版预发布检查摘要。

## 4. 第 13 节（Capstone）

- 看懂标准：能把“需求 -> 改动 -> 验证 -> 风险”串成闭环。
- 动手动作：完成 `docs/learning/13-capstone.md` 的一份真实提交。
- 留痕建议：保证他人不追问也能复盘你的改动。

## 5. 结业建议

1. 00-12 每章至少留一条证据。
2. 完成第 13 节 Capstone。
3. 写一页收官笔记：你最有把握的 3 点、最不稳的 3 点、下一步补强计划。
