# 第 13 节：Capstone（结业实战）

## 目标

把前 13 节知识串成一次完整工程闭环：需求 -> 设计 -> 改动 -> 验证 -> 结论。

## 题目（固定）

为 `binlog_server` 做一次“可审计的小改动”，并提交完整证据链。

可选方向（任选其一）：

1. 文档增强：补齐一个你认为会误导新同学的章节并给出前后对照。
2. API 可观测增强：新增一个只读排障字段（不改业务语义）。
3. e2e 场景增强：为已有 smoke 场景补一个关键断言。

## 约束

1. 改动必须小而完整（建议控制在单一主题）。
2. 不能只“改了就算”，必须有验证证据。
3. 结论必须包含风险边界（哪些没覆盖到）。

## 交付物

1. 变更说明（What/Why）。
2. 验证命令清单（至少 2 条）。
3. 关键输出摘要（可复查）。
4. 风险与后续建议（最少 2 条）。

## 推荐模板

```md
### 1) 需求

### 2) 设计决策

### 3) 改动文件

### 4) 验证命令与结果

### 5) 风险与限制

### 6) 是否达到发布门槛
```

## 评分标准

1. 完整性：需求、实现、验证、风险四要素齐全。
2. 可复现性：他人按你的命令可得到同类结果。
3. 工程性：不引入额外语义偏差。
4. 表达质量：结论清晰、证据先于观点。

## 完成标准

1. 交付物齐全。
2. 验证链路可复现。
3. 评审者可在不追问的情况下复盘你的改动。

## 5 分钟最小实操

1. 选一个小改动方向（文档/API/e2e 之一）。
2. 用模板写出“需求 -> 改动 -> 验证 -> 风险”四段。
3. 保证别人只看你的记录就能复盘，不需要追问背景。
